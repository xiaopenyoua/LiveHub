## 按钮改 Liquid Glass（tvOS 26 方向）

用户反馈两条：按钮不该是纯色、按钮切换要有动画。调研后按 Apple 官方口径重做材质与动效。

### 关键调研结论
- tvOS 26 控件材质是 **Liquid Glass**：半透明、吸收并模糊背后内容、带镜面高光。
- Apple 对 `CustomHoverEffect.highlight` 的描述：tvOS 上是 *projection effect accompanied with a specular highlight*，并随运动调整高光偏移。
- tvOS **内置 focus hover 时长 ~200ms**（透视抬升 + 镜面光泽）。这是时间参数的权威来源。
- 自定义动画要挂在 focusable 的**子元素**上，挂元素本身会与内置 hover 打架产生抖动（现有 `.card.is-focused .card__lift` 写法正好是对的）。

### 材质实现（四层，全部 inset）
底色半透明白 + `backdrop-filter:blur(24px) saturate(180%)`；顶沿 `inset 0 2px 0 rgba(255,255,255,.98)`；底部柔暗 `inset 0 -16px 24px -10px rgba(0,0,0,.24)`；底沿窄暗 `inset 0 -3px 5px -3px rgba(0,0,0,.22)`。
- 白主按钮实测顶部行亮度 246 / 底部 229，差 17 级。
- **不用 linear-gradient**：渐变不可过渡，焦点切换会硬切；`box-shadow` 能插值，高光才跟得上。
- **不做外投影**：真黑底上无效（这条沿用上一轮结论）。
- 小控件（分段选中块、开关轨道）用 `--spec-chip` 短版，避免 16px 柔暗压脏。

### 动效
`--dur:200ms`、`--dur-press:120ms`、`--ease:cubic-bezier(.32,.72,0,1)`。
`--t-surface` 必须含 `box-shadow`，否则"块变大了、光没跟上"。
顶栏改**焦点胶囊**：`.tabs__pill` 绝对定位，用 `offsetLeft/offsetWidth` 定位（**不能用 getBoundingClientRect**，读到的是过渡中间值会跑偏）；换屏传 instant 避免跨屏滑动。260ms。
顺带把 tab 从 `padding:10px 2px`（约 50px 高）扩到 `11px 24px`，解决上一轮遗留的"最弱焦点目标"。

### 闸门边界（重要，以后别再踩）
- lint 的 `shadow` 在 app 模式降级 WARN；`glass` 本来 WARN；`gradient` / `button-fx` **不降级**。
- **lint 的 appMode 读 `.taste-skill/direction.json`，而本项目该文件在 `.taste-skill/app/` 下**，所以必须显式带 `--app`，否则 shadow 按页面规则判 FAIL。
- inspect 的 `judgeApp` 里**没有** gradient / button-fx，但 `judge()` 路径会跑，所以仍会报 `button-fx`（`m.buttons.withShadow` 连 inset 也算）。
- `heavy-shadow` 只看**非 inset** 的外阴影，且 darkGround 下 `alpha>=0.45` 才算重；`inset` 直接跳过。
- 结论：按钮玻璃必须 `--allow button-fx`，理由已写 README（18→20 处全是 inset，逐条核对过）。

### 结果
lint 0 FAIL / 31 WARN；inspect 0 FAIL / 1 WARN；selftest 12 步全通，焦点困住 6/40 不变。八张截图已重出。

## 补收尾：设置页左右同源 + 导航算法重写

### 先排掉一个假警报
上一轮 `verify-groups.mjs` 报「默认焦点没有」，是**测试产物**：该脚本在结尾前循环调 `renderPanel()` 重写了 `#sPanel` 的 innerHTML，把持有焦点的 DOM 节点销毁了。

### 顺手修掉三个真问题
1. **卡片副文本 22 → 18px**（新增 `--fs-card-meta`）。26/22 只差 4px，三米外糊成一片读不出主次；退到 18 拉出 1.44 倍。副作用：inspect 的 `headline-lines` @768px FAIL 自动消失 —— probe 的 `clean()` 判据是「块内有没有小于 0.72 倍的文字」，22/26=0.85 让它把「台号+标题+副文本」当成一个标题块量行数。这不是绕规则，是把规则想指出的层级问题真解决了。
2. **设计稿外壳对比度**：`.chrome__title span` `#8E8E93`(2.8:1) → `#5F5F64`(5.4:1)；`.hintbar` `#6E6E73`(4.3:1) → `#5F5F64`。
3. **四向键导航算法重写**（见下）。

### 导航算法：中心点距离 → 边缘间隙
旧：`primary = 中心点距离`，`score = primary + secondary*2.4`。
病：设置页从左侧导航按右，顶栏「首页」水平中心只差 **37px**、右侧设置行差 **904px** → 焦点窜到顶栏。窄而长的元素在中心距离上永远占便宜。

新（`moveFocus`）：
- **筛方向仍用中心差**（`mainCenter > 4`）—— 首页按右要能到 301，而 301 卡左边缘比按钮左边缘还靠左（间隙为负），只有中心差能救它。
- **排序用边缘间隙**，副轴间隙 **×3**。
- 副轴间隙 = `max(c.top-o.bottom, o.top-c.bottom, 0)`（重叠记 0）。**踩过坑**：第一版写成 `min()`，结果副轴不重叠时永远得 0，权重完全失效。

验收：五屏 125 个 focusable × 4 方向 = **500 次，非边界卡住 0 次**。
副作用验证：首页 ArrowRight 回到 301（不再跳 103），设置页左栏 ArrowRight 回到「解码方式」（不再窜顶栏）。

## 第二轮：五条界面需求（关注按钮 / 开关动效 / 三处滚动）

### 需求与落地

1. **播放页 `＋ 关注` 移到控制条末尾** —— 从首位挪到 `换台` 之后。理由：前四个是"看这一次"的参数，关注是"以后都看"的动作，它是出口不在这条参数链上。副作用：`DEFAULT_FOCUS.player` 解析到 `弹幕`，截图里 05-player 的焦点读数是「弹幕」。
2. **开关切换动画重做** —— 用户只说"不流畅"，用 CDP 每 20ms 采样位移+颜色才定位到成因（见下）。
3. **首页改竖排网格可整页滚** —— 单行横滑 → `.card-grid` 4 列，`HOT` 扩到 12 条（3 行）。实测 `scrollH 1773 / clientH 964`，滚到底最后一张卡底边 y=950 完整可见。
4. **分类页 / 设置页左栏固定** —— 拆掉外层 `.scroll`，`.browse` / `.settings` 直接作为 `.screen` 的 flex 子项 + `min-height:0`，右栏独立 `overflow-y:auto`。
5. **搜索页键盘固定** —— 同上，`#searchScroll` 独立滚 250px，`.kb` 不动。

### 开关动效：四轮迭代的数字

- v1 借焦点曲线 `.32,.72,0,1` + 240ms：**前 86ms 走完 83%**，剩 150ms 只挪 6px → "冲一下然后卡住"。
- v2 过冲曲线 `.34,1.4,.64,1`：64ms 走完 80%，滑块早到站，轨道追不上；且 alpha 顶到 1 提前饱和（129ms 就到 `rgb(255,255,255)`）。
- v3 拆 `--sw-ease-track` 单独调轨道：滑块前 64ms 走完 80%，轨道怎么调都追不上。
- **定案**：`--dur-sw:180ms` + `--sw-ease:cubic-bezier(.4,0,.2,1)`（位移与轨道共用）+ `--dur-sw-color:120ms` + `--sw-delay:55ms`。采样每 20ms 推进 **0.8 / 10.9 / 9.2 / 6.6 / 7.1 / 1.7 / 1.1 / 0.5**，末端 3.4px 摊 72ms。
- 三条结论写进规范 7.2：变速与位移不能同起同止；颜色曲线不能过冲；轨道必须和滑块同一条曲线。

### 关键实现点

- **`min-height:0` 是 flex 内滚的必要条件**，缺了它 `overflow-y:auto` 永远不生效（子项默认 `min-height:auto`）。
- `.panel` 需要 `align-self:flex-start` + `max-height:100%` 两行同时存在，缺一个都错。
- 面板自滚后**换分组必须手动 `scrollTop = 0`**，否则新分组从上一组的滚动位置开始。
- 设置项从 15 项扩到 23 项 —— 原内容 773px 恰等于可视高，`overflow:auto` 写了但一条都不用滚，特性等于不存在。现可滚 103px。

## 第三轮：搜索键盘改 QWERTY + 支持数字

### 用户纠正（最重要的一条）

第一版把数字键当成「台号专用输入」，写了 `if(kbMode==='num' && cur.length>=3) return;`，第四位不接收。用户一句 **「有可能主播的名字也有 数字呀」** 直接推翻：主播名里常带数字（小鹿233、LPL解说666），按「数字键只能输台号」去限三位，等于告诉这些主播不存在。

改法：删掉位数限制，只挡输入框容量（12 位）；徽标从「台号」改成「数字」；占位文案改「输入台号，或含数字的主播名」；`ROOMS` 里把 `小鹿` 改成 `小鹿233`（`py:'xl233'`）做实证。

### 结构

- QWERTY 十列 + 短行错位：第二行缩半键、第三行缩一键半，缩进用 `calc((100% + 14px)/20)` 与 `*3/20` 按列宽算，不写死 px。
- 数字键**一行五个、每键占两列**（实测宽 164.1px）。一行十个每个只有 70px，三米外是在瞄手指宽度。
- **两种键盘模式必须等高**，否则切模式工具行会跳：字母 92×3 + 14×2 + 92 = 410，数字两行要 `2H + 14 + 14 + 92 = 410` → **H = 145**。实测两模式工具行 `top` 都是 **745**。
- 切模式重建键盘后**必须重新 `setFocus`**，原焦点节点已不在文档里。

### 搜索结果

- 排序「台号 > 主播名 > 标题 > 分类」，`searchHits` 带 `rank` 排序；`go` 键永远开 `hits[0]`，于是「直达提示」和「搜索键行为」不可能不一致。
- 键盘从 740 加宽到 830 后结果区只剩 966px，`.results .card-grid` 用 `minmax(280px,1fr)` 硬塞 3 列 → 282px 的卡放 26px 标题，全被截成「第…」。删掉覆写，回落 `.card-grid` 的 400px 下限 → 2 列。**搜索结果最需要读的就是标题，宁可少一列。**
- 空查询不显示结果（原来固定摆 4 张卡＝告诉用户"什么都没输也有结果"），最近搜索 `is-lead` 顶到最上。

## 第四轮：照 Apple tvOS 官方规范自查（用户指定两页原文）

新增交付 **`docs/03-Apple规范对照.md`**：逐条对照 + 实测数字，分「符合 7 / 已改 4 / 取舍 2 / 未覆盖 2」四档。

### 改掉的四处（都能量）

1. **播放页整幅压暗**（最实的一条）。原来 `#pvVideo{filter:brightness(.78)}`、idle 时 `.92`。实测四张封面：这层压暗对顶栏文字对比度只贡献 **+0.4～+1.0**（19.4→19.0），代价是画面亮度直接乘 0.78。改成 `filter:none` + 只在顶/底两条带加深遮罩（36%–55% 中段一点不碰），`idle` 时遮罩 `opacity:0` 淡出。
2. **换台提示对比度**：`--faint` 落在最亮封面（LED 墙）只有 **2.55:1**。改 `--muted` + 底栏遮罩加深 → 最差 **4.74:1**。
3. **返回不记忆焦点**：`screenFocusMemory` 表写了、`showScreen` 也读，但**从来没人传过 `opts.remember`**，永远空表＝死代码。改成 `data-back`/Escape 带 `remember:true`，并加一道「记忆节点是否还在这一屏」的校验（切平台会重建列表）。实测：第 5 张卡(205) → 播放 → 返回，焦点仍在 205。
4. **字阶有 1px 台阶**：19/20/21/23/28/36/38 七个脱离令牌的硬编码值，21 与 22 只差 1px。收敛到 `--fs-small:20` 等令牌后，每屏 6–8 档、相邻最小间距 2px。**档位多不是问题（Apple 自己的 ramp 有 11 级），1px 的台阶才是。**

### 另外

- `.srow` / `.rrow-s` 没有按压态（`press()` 加了 class 但没 CSS 规则）→ 覆盖率 125/136 → **136/136**。
- 播放页提示写「返回键回首页」，实际第一次只收控制条 → 改成两步描述。
- 焦点放大挤压实测 **0/130**（逐个聚焦量包围盒交叠），这条是符合的，不用改。
