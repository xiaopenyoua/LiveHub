# design/

设计侧的全部产物。**归属判据不在本文件，在仓库根的 `AGENTS.md`** —— 两者冲突时以 `AGENTS.md` 为准；
本文件只讲 `design/` 内部怎么摆、文件怎么起名。

`design/` 和 `android/` 的关系是**单向**的：设计先行，工程对齐设计。任何"界面上该长什么样"的争议，
回到 `v1.0.0/ui.html` 看，不看代码。反向不成立 —— `design/` 不读 `android/`，也不写 `android/`。

## 四个并列的段

```
design/
  brand/          品牌图形：矢量真源 + 交付位图      （规矩见 brand/README.md）
  system/         跨版本设计规则：现行有效的规范文本
  media/          稿子的运行时素材：稿子以相对路径引用的字体与图片
  v1.0.0/         一个版本一个文件夹，定版即冻结
```

四条各回答一个问题，互不重叠：

| 段 | 回答 | 只进 | 永远不进 |
| --- | --- | --- | --- |
| `brand/` | 品牌图形长什么样 | `wordmark/src/*.svg`、`wordmark/export/*.png`、光栅脚本 | 任何 `res/` 形状目录、Android XML |
| `system/` | 跨版本都成立的规则是什么 | 当前有效的规范文本 | 版本目录、并存两套值（历史在 git） |
| `media/` | 稿子运行时靠什么渲染 | 字体、封面图 | 矢量（归 `brand/`）、截图、`res/` |
| `v1.0.0/` | 这一版定稿长什么样 | 定稿稿、`spec/`、`shots/`、`screenshots/` | 跨版本素材、下一版草稿 |

**下一版另开 `v1.1.0/`，不在 `v1.0.0/` 里改。** 定版即冻结：改一个字也是新版本，因为冻结的那份是
"当时用户点头的东西"，它一旦可改，就没人能回答"用户当时点头的是哪一版"。

## 命名规矩

**文件名 = 它画的那件事。**

1. 全小写，kebab-case，扩展名 `.html`。
2. **不写版本号。** 版本由所在的版本目录承担；`v1.0.0/splash.html`，不写 `splash-v1.html`。
3. **不写状态词与代号词。** `index` `preview` `final` `draft` `new` `old` `copy` `v2` `a/b` 一律不用 ——
   这些词描述的是"它处在什么阶段"，不是"它画的是什么"。
4. **一个词优先。** 一个词够用就不用两个；同目录下确实有多份同类稿子时，才加限定词（`player-focus.html`）。
5. **目录已经表达的，文件名不再重复。** 开屏稿叫 `splash.html`，不叫 `app-splash.html`。

### 位级：这套规矩管谁，不管谁

| 位置 | 受命名规矩管？ | 能写 `NN-` 前缀？ |
| --- | --- | --- |
| `v1.0.0/*.html`（三个定稿） | **是** —— 它们是这套规矩的对象 | 否 |
| `v1.0.0/shots/*.png`、`v1.0.0/screenshots/*.png` | **是** | 否（编号只被当排序用，起不到地址作用） |
| `v1.0.0/spec/*.md`（六份） | 部分 —— 序号是**承重地址**，例外 | **是，全仓库只有这一处** |
| `brand/wordmark/{src,export}/*` | 是，但用尺寸名：`square-<像素>`、`banner-<宽>` | 否 |
| `system/*.md`、`media/**` | 是，语义名 | 否 |

`spec/` 用 `NN-中文标题.md` 的理由只有一个：版本内互相裸号引用上百处（"见 03 §7"），编号是地址。
**编号是永久地址：作废不复用，允许空号。** 现在是 `01,02,03,04,07,08`，05/06 是历史空号，
**不要拿它们给新文档补位** —— 补位等于把一条旧引用悄悄指到别的文档上。

## 版本目录里放什么

```
v1.0.0/
  ui.html            六屏可交互原型（单文件、无构建、1920×1080）
  splash.html        应用内开屏（单文件，带动效与 ?t= 时间轴）
  icon.html          应用图标：矢量源 / 自适应三层 / mask 裁切 / 五档 mipmap / monochrome
  spec/              六份规格与裁决（唯一能用 NN- 前缀的地方）
    01-图标概念-品牌裁决.md
    02-图标几何规格.md
    03-开屏视觉规格.md
    04-开屏动效与字阶.md
    07-字标图标与开屏规格.md
    08-品牌裁决.md
  shots/             开屏定稿帧（3 张，名字说清是哪一态：splash-crossfade / splash-still / splash-sys）
  screenshots/       原型定稿截图（10 张，名字说清是哪一屏：home.png / channel-osd.png …）
```

**三个定稿稿子一律放在版本目录顶层。** 稿子是给人看的，规格是给人查的，不混在一起 ——
`spec/` 里是裁决证据，不是"设计稿的附件"。

- **稿子（`.html`）自包含**：单文件、无构建、双击能开。它们引用的素材是 `design/media/` 里的字体与封面、
  以及 `design/brand/wordmark/export/` 里的位图。**稿子里按"相对稿子所在目录"写相对形式** ——
  这是设计侧内部唯一允许的引用形态。改了 `media/` 或 `export/` 的位置，必须同步改稿子里的路径，
  否则稿子双击开就是白屏。
- **`shots/` 与 `screenshots/` 可以重拍、可以删。** 它们是留痕，不是源；不写进文件名序号，因为
  "第几张"不是地址，屏名才是。
- **`spec/` 只许在文首加 errata，不许改正文。** 目录一动，正文里 `git show HEAD:…` 那些历史命令
  就"指不到"了，但**"文件没了"和"证据没了"是两件事** —— 正文保留原样作历史坐标读，
  新路径写在文首那条 `> 路径时效（YYYY-MM-DD）：…` 里。六份现在都有这条声明。

### 新增稿子怎么起名

| 要画的 | 命名 |
| --- | --- |
| 播放页的换台条专项 | `v1.1.0/player-osd.html` |
| 设置页单独一稿 | `v1.1.0/settings.html` |
| 图标在小尺寸上的专项（LH 与完整字标的分界） | `v1.1.0/icon-small.html` |
| 品牌色板（**注意**：品牌资产归 `brand/`，不放版本目录） | `brand/` 下的规范文本，不是 `v1.1.0/brand/palette.html` |

同一版本目录里文件名不得重复；跨版本可以同名 —— `v1.0.0/ui.html` 与 `v1.1.0/ui.html` 是同一件东西
的两代，靠目录区分，不靠文件名。

## 为什么不用 index.html

静态服务器会把 `index.html` 当目录默认页。多个版本目录各有一个 `index.html` 时，
`/design/v1.0.0/` 与 `/design/v1.1.0/` 在浏览器里都显示成同一个"index"，跨版本对照时就分不清谁是谁。
文件名说清楚画的是什么，比依赖目录默认页更可靠。

## 什么不进 design/

- **`assets/`** —— 它已经不存在了，拆成了 `media/`（稿子素材）与 `brand/wordmark/`（品牌源与位图）。
  以后也不许再建：这个名字不回答"是谁的产物"，于是每个进来的人都会往里扔不同的东西。
- **Android 资源**（`mipmap-*` / `drawable-*` / `values`）—— 那是 `android/` 的字节，
  在 `design/` 下再存一份就是第二个真相源。
- **`build/`、`tmp/`、`out/`** —— 光栅化默认输出到 `$TMPDIR`；要落盘的只有 `brand/wordmark/export/`。
- **取证截图批** —— 那一轮的证据在 `spec/` 的文字里；截图批本身是过程物。
