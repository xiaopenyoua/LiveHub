## 2. 时序实测

### 2.1 结构（浏览器动画对象上的真值，不是墙钟）

在 `#stage` 上加 `.is-exiting` 之后枚举 `getAnimations({subtree:true})` 读 `duration / delay / endTime`：

| 动画 | 目标 | duration | delay | endTime |
| --- | --- | --- | --- | --- |
| `splashOut` | 开屏层（E1） | 200ms | 0 | **200** |
| `homeIn` | 首页内容（E2） | 240ms | 0 | **240** |
| `homeIn` | 顶栏结构（E3a） | 240ms | 0 | **240** |
| `homeIn` | 顶栏 30px 字标（E3b） | **80ms** | **200** | **280** |

→ **A = T+200、B = T+280**，与冻结表一致。reduced 下四条全部 `16 / 0 / 16`，即 **A = B = T+16**。

### 2.2 墙钟（`animationend` 采样）

| 场景 | T | 退场起 | A 实测 / 标称 | B 实测 / 标称 |
| --- | --- | --- | --- | --- |
| 就绪 760 | 960 | **961** | **1188** / 1160 | **1255** / 1240 |
| 慢就绪 1200 | 1400 | 1401 | **1626** / 1600 | **1693** / 1680 |
| 超时 1500 | 1700 | 1701 | **1945** / 1900 | **2012** / 1980 |
| reduced | 960 | 962 | **988** / 976 | **988** / 976 |
| 四家全失败 | — | — | 不退出（`Async.Failed`，停在降级态） | — |

**墙钟为什么系统性晚 10–45ms，而这不代表时长写错：** 截图机是无 GPU 的 headless，合成帧 25–45ms 一拍（真实 60fps 是 16.7ms），`animationend` 落在动画结束后的第一帧上，晚的是一整帧的采样，不是时长。三个证据：① 上面那张表的 `endTime` 精确命中 200/240/280；② 最轻的路径（reduced，四帧就结束）晚得最少，只 +12ms；③ 最重的路径（timeout，此刻首页大图正在合成）晚得最多，+45ms —— 延迟跟着合成负担走，跟着动画走的是零。**报数时红线看 A（T+200），对外用 B（T+280），两者差 80ms 就是 E3b 那段。**

`measure.json` 里同时存了墙钟与标称，键名按冻结表：`tExitStart` / `tClearedA` / `tHomeSettledB`，另有 `byState` 与 `structure`。

### 2.3 入场（P1–P3）

| 帧 | 内容 | 证据 |
| --- | --- | --- |
| t=0 | 只有图标，在屏幕中心、192px、**alpha 已满** | 墨迹 909–1007 / 468–603，与段 1 帧同 bbox |
| t=340 | 图标已停在终位，字标**还不可见** | 墨迹 907–1009 / 257–398；整帧无字标像素 |
| t=600 | 字标到满，状态行还不可见 | 墨迹含 737–1185（字标），y 内无 22px 行 |
| t=960 | 入场收束 | 与就绪终态 md5 相同（`7752f6226626b88f98e283624c490c56`） |

`t=960` 与静止终态逐字节相同，说明「CSS 默认值 = 终值、动画只负责从哪里来」这套写法没有残差：动画到点就落在默认值上，不存在「动画结束后回跳 1px」的经典问题。

## 5. 七处「规格与实现打架」，逐条交代

前四条是规格里的数在像素上不成立，后三条是两份文件之间已经被你裁过、我按最新口径实现的。

### 5.1 降级态「x 862–1058 / 宽 196」塞不下自己的文案 —— 已改为中心轴 960

03 §6 给标题和说明的框是 862–1058（196 宽）。实测两条都装不进去：

- 标题「四家平台都没连上」8 字 × 34px = **272**（>196，超 39%）
- 说明「网络在，但四家都没有响应。稍等片刻再试一次。」22 字 × 24px = **528**（>196，超 169%）
- 若强行 196 宽：说明要折 3 行，给定的「baseline 746」不成立，且第三行会压到 776 的按钮上

**做法**：整块以 **x=960 为轴居中**，标题单行（实测墨迹 826–1094）、说明单行（698–1209）、按钮 894–1026。注意按钮的左右缘与 03 §6 给的 **894–1026 一字不差**（132 = 2×26 + 2×40），说明居中是这一组数唯一自洽的读法 —— 862–1058 大概是 §5 状态块那一行被复制过来了。

**副作用要你裁**：说明单行 528 宽，比字标（461.9）还宽 66px，纵向栈的「字标最宽」被破了。要它窄于字标只有一条路：说明折两行、按钮下移到 ~810。那是改版面，我按现规格没动。

### 5.2 字标 461.7 需要 `font-optical-sizing:none`，否则窄 6.7%

`assets/fonts/InterVariable.woff2` 是可变字体，带 `opsz` 轴。120px 下浏览器默认 `font-optical-sizing:auto` 会把字标切到 Display 光学尺寸：

| 取法 | 排版宽 | 对 461.7 |
| --- | --- | --- |
| `auto`（默认） | 430.86 | **−6.7%，落在 448–476 窗口外** |
| `none`（opsz 锁 14） | **461.91** | +0.05% |

03 §4 的 3.847em 是在默认光学尺寸上量的，所以这一行不是调字号，是**把字体按规格取用的方式取用**。已加 `font-optical-sizing:none` 并在源码里写明理由。若你认为 120px 该用 Display 切法（排版上说得通），那就是改规格的数：461.7 → 430.9，验收窗口整体下移。

### 5.3 120px 的基线会被吸到整像素：公式算 582，实测要补 1px

行盒顶到基线的距离 = `0.8633em`（= 0.5em + Inter capHeight/2，由 hhea 1984/496/2048 推出）。22px / 24px / 26px / 30px / 34px 全部落得准（四行基线与降级态三行都是 0 误差），**只有 120px 会落在 582**：Chrome 在这一档把基线吸到上一格整像素。已补 1px，实测 baseline 583.00、cap 顶 495.91。源码里那一行写成 `calc(583px - .8633em + 1px)` 并注明来源，不是魔术数。

### 5.4 「居中于 960」在墨迹上必然 +1

见 §1 末。按排版宽居中是 **960.00**，墨迹中心是 **961.0**，两者不可能同时为 960 —— 差的是 Inter 的左右边距差（7.95 vs 5.95）。我选了排版宽（= Compose `textAlign=Center` 的行为）。

### 5.5 E3b 是 80ms / T+280（不是 04 §3.2 的 40ms）

04 §3.2 的表写「T+200 → T+240，40ms 内到 1」，你最后一封信冻结为 **T+200 → T+280（80ms）**，B = T+280。已按冻结表实现，`endTime` 实测 280。**04 那张表需要回写**，否则下一轮会照着 40ms 再吵一次。

### 5.6 reduced-motion 下 A = B = T+16（不是 04 §5 的 32ms）

04 §5 说「E3b 单独再 1 帧，合成 32ms」；冻结表给的是 A = B = 976（= T+16）。两者不可能同时成立：**E3b 要是单独一帧，B 必然比 A 晚 16ms。** 已按冻结表实现（四条动画全部 `16 / 0 / 16`，实测 A = B = 988）。代价是 reduced 下两处字标同帧切换 —— 但那本来就是一次硬切（reduced 的定义就是没有过程），而 04 §5 要保的是「两个字标不同框」这条**结构**，在 16ms 里它无法被感知。**04 §5 的 32ms 与冻结表的 976 需要你定一个。**

### 5.7 首页层的底色是 #000000，不是 `index.html` 的 #15161A

`index.html` 的 `--ground:#15161A` 是网页原型的暖黑；`Theme.kt:33` 的 `Ground` 是 `#000000`。开屏层与首页层都不携带自己的底色、底色只在根 Box 上给（04 §4），所以首页层也必须是 `#000000` —— 否则 E1 淡出的那 200ms 里底色会从 #000 跳到 #15161A，正是 04 §4 禁止的那次亮度跃变。

**首页按你的要求只做最小可信一屏**：顶栏（玻璃胶囊 + 五页签 + `Live`白`Hub`红 30/600，字标 baseline 实测落在 69）+ hero（`esports-arena` + 标题 76/600 + 白胶囊按钮）+ 一行三张卡（`night-track` / `hotpot` / `livehouse`，380×16:9，r=20）。**没有复制其余五屏，没有引入 `index.html` 的任何脚本**，只沿用它的令牌（`--nav-h:116`、`--gut:80`、`--r-card:20`、`--ease`、字阶数值）。
两处刻意的减法：① 右上角只留「有线网络 21:14」文字，没有 `index.html` 的绿点（绿是首页状态色，开屏这套五值里没有它，不想让取证图里出现第 6 个颜色）；② 三张卡里只有第一张提亮标题当「有焦点」，不做 1.08 放大 —— 冷启动后焦点还没落，放大反而是假戏。

## 7. 判定

**可以拿去评审：十项版面读数全部命中（最大偏差 0.21px，出现在字标宽与 cap 高，来源是字体版本而非定位），颜色集合 5 值 / 第四色 0，A/B 结构与冻结表一致，`t=960` 与终态逐字节相同。**

真正需要你回一句的只有三件：① 降级态说明单行 528 宽要不要为它改版面（§5.1）；② 字标用不用 Display 切法（§5.2，会改掉 461.7 这个数）；③ 04 的 40ms / 32ms 两处要不要回写成 80ms / 16ms（§5.5、§5.6）。
