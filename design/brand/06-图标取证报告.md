## 0. 结论先行

| 48 | 118/2304（5.12%）Δmax 79 | **0/2304　Δ 0** |
| 72 | 0/5184　Δ 0 | 0/5184　Δ 0 |
| 96 | 209/9216（2.27%）Δmax 92 | 92/9216（1.00%）Δmax 11 |

### ③ 48 档黑缝 —— PASS（但光栅余量为 0）
判据（02 v1.2 §3）：缝内**最窄一列有 ≥3 个竖直纯黑像素**且无灰桥。缝是斜的（32.6°）横跨多列，数「有几列黑」没有意义，只数那一列里的竖直纯黑像素。
五档实测（最窄列纯黑数 / 位置 x）：**48 → 3 @23**、72 → 5 @35、96 → 8 @46–48、144 → 13 @69–73、192 → 18 @94–99，全部 ≥3。**只有 48 档正好落在下限上（3 对 3，余量 0 像素）。**
48 档逐列 `23:3 24:4 25:5 26:5 27:6 28:6 29:7 30:8 31:8 32:9 33:10 34:10 35:11`；把边界从「任意墨迹」换成「≥50% 实体」重算，最窄仍 3 —— 结论不依赖阈值。法向缝 3.10 → 同 x 竖直净空 3.68（48 档取整后斜率 16/25，换算系数 ×1.187；矢量原值 24/37 时是 ×1.19203）；实测纯黑 3 ⇒ **抗锯齿吃掉 0.68px**。所以「余量 21%」是**法向**口径，换成光栅口径是 **0**。若照 0.08H 下界画（法向 2.56 → 竖直 3.05），AA 后剩 ~2.4 即 2 个纯黑 → 粘连，与 02 v1.2 的推演吻合；本轮没发生。
**灰桥 0 个**：缝内非纯黑像素 48 档 **0 个**（不是"没找到含白+红的"，是"缝里连一个非纯黑都没有"）；72/144/192 各 1 个，全是三角形自身边缘的 AA 溢出（RGB `(1,1,1)`、白分量 0.004、红分量 0，坐标 (40,26)/(94,62)/(99,66)），不含红；96 档 0 个；全图含白+红双墨像素 **0 个**。拓扑复核：墨水连通域在阈值 0.5 与 0.02 下，48/96/192 三档都**恰好 2 块**（一白一红），从未连成一体。证据：`ev-icon-03-seam-5sizes.png`（五档逐格放大，蓝框 = 最窄列那段纯黑）、`ev-icon-03-48px-8x-nearest.png`

## 2. 缺陷（按严重度）

**A · 阻断 · 新图标没进宿主工程。** `android/app/src/main/res/` 五个密度桶全是旧图（底色 #0C0C0E），v26/v33 两个 adaptive-icon、两个 VectorDrawable、一个颜色资源一个都没有。即使现在打包，Android 13 主题图标仍缺失，桌面仍是旧的「白三角＋正圆红点」。`05` §1 把 `android/` 列为范围外，所以这是**范围决定不是失误**，但它是"资产落地"唯一没兑现的一环，必须由主理人派工或明确宣布本轮不落地。

**B1 · 次要 · 48 档黑缝的光栅余量是 0，不是 21%。** 02 §3 说「几何有余量 21%」（第 96 行）与「任何一档都踩不到 3px 下限」（第 97 行），那是**法向**口径（法向 3.10 对 2.56）；判据本体是**纯黑像素数**，48 档实测正好 3 = 下限，AA 已吃掉 0.68px。它没违规，但"还有 21% 可让"会被读成"可以再压 0.5px"——压 0.5px 就掉到 2 个纯黑即近粘连。建议 02 v1.3 把这两句改成「法向余量 21%，光栅余量 0；未违规但不得再压」。

**B2 · 次要 · 96 档宽高比 2.250 正好压上限，零余量。** 27÷12 = 2.250 与判据上限是同一个数（02 §3 已声明允许），徽章宽一次取整改向即刻出界；反向的坑在 48 档 2.167，而 02 §3 表把它写成 2.17，谁拿 2.17 当硬下限就会以 0.15% 误差踩线。建议判据统一写「2.16–2.25」，不要单点断言。

**B3 · 次要 · 「最紧处距心 32.45 / 余 0.55」仍量在虚点上（02 §6.10 第 166 行、05 第 197 行）。** v1.1 已把**缝**这一项修对（§3 给出实体 4.24/5.94/7.64/11.88/16.13，我五档逐一复核全部相符，k=1.369–1.432），但 §6.10 的安全圆余量还留着 bbox 角点 (72,27) —— 那个点被 r=4.5 圆帽整个切掉了。真实最远点在右端圆弧 (69.82,27.64)，距心 **30.739**、余量 **2.26**（非 0.55）。方向安全，但按 0.55 排「不许在此附近加东西」会把 3.4 倍余量当零。

**C1 · 记录 ·「最右列」的判色口径曾经没定义，现已由 02 v1.1 定死为任意覆盖。** 我复核两套口径的差异只出现在**判 ink**（50% 口径五档假失败）；**判 bbox**（宽高比）两套结果完全同值（13×6 / 20×9 / 27×12 / 40×18 / 53×24），所以口径没定死也不会算错分析数。建议顺手补一句"bbox 亦用任意覆盖"，把最后一个开口封掉。

**C2 · 记录 · 48 档 PNG 与 SVG 母版在 118 个像素上画的不是同一形状。** 02 §2 强制整数坐标，48 PNG 是"取整后重画"，与 SVG 精确几何差 118/2304（5.12%）、Δmax 79。这是规格要求的结果不是错，但拿 48 PNG 反推矢量会偏最多 0.33px（72/144 恰落在整数网格，差 0）。

**C3 · 记录 · `05` §5.4「实测最短中心距 4.47px」与我的实体距 4.24 差 0.23px。** 是「整像素边界中心距」与「亚像素实体距」的口径差（半像素量化），方向一致（都证明实际 > 名义 3.10），但它被写成了实测值，下轮不宜再引用。

**C4 · 记录 · 预览页 02 区块外形像 lockup。** 「TV 桌面语境」把 48px 图标与 34px 字标横向并排＋垂直居中，图标墨迹高 32 vs 字标 cap 高 24.9，严格说不构成 `01` §6「等高并列」违规，页面也标了「图标 + 应用名」。风险是它是 OS 排布模拟却长得像品牌 lockup，下一轮做开屏版式容易直接抄走。建议加一行"这是系统桌面排布，不是 lockup"。
## 3. 我试过但没破的破坏方式

1. **位图缩放指纹**：4 条缩放路径（192→48/96、96→48、144→48）都做 box 平均，最好的仍差 130px，原生回渲差 0px。48 比 192 更准本身就否掉缩放假设。
2. **第四色**：先定混合模型再逐像素求残差（阈值 2，后收紧到 0.9），74,304 像素 0 个越界；再用「白+红联立最小二乘」专找双墨混合 → 0 个。
3. **灰桥 / 缝污染**：缝边界从「≥50% 实体」收紧到「任意墨迹 0.004」，48 档最窄列仍 3 个纯黑、缝内非纯黑像素仍 0 个；把缝内所有非纯黑像素列出来，只有 3 个 1/255 的白边溢出，一个红的都没有。
4. **粘连**：墨水掩码 4 连通域，阈值 0.5 与 0.02 两种、48/96/192 三档，都恰好 2 块，从未合并。
5. **monochrome 底板**：四角＋四边中点 alpha 全 0；10× 下两块 bbox 之和远小于 108×108；找不到"比三角更大的矩形"。
6. **缝 alpha**：最近点连线 201 个采样，196 个严格 =0，另 5 个是形状自身边缘 —— 缝是真 alpha=0，不是"同色被看成一条缝"。
7. **缝宽不够**：解析（圆心到斜边 − r）与 10× 点内光栅 + BFS 距离变换（`design/.ev-seam.mjs`，完全不吃 PNG）两条独立路径，五档结果 4.24/5.94/7.64/11.88/16.13 与 10× 复核值互差 ≤0.42（离散化），无一项跌破名义值 —— 「画窄了」不成立。
8. **右缘**：五档都用任意覆盖扫到最右列，同列；也试了 ≥50% 实体口径（会假失败，已写进 C1）。
9. **md5 / 1:1**：五档 `mipmap-*` 与 `icon/png/` 逐个一致；作者 `shots/icon-48/96.png` 与实际 PNG 逐像素 0 差；预览页 `naturalWidth` 与 CSS 宽度五档全等、dpr=1。
10. **换口径复核**：红墨换 108 画布分母（1.368–1.401%）、宽高比换任意覆盖 bbox、缝换 ink-to-ink 与 10× 实体距 —— 没有一项从 PASS 翻成 FAIL（除那个已知的 50% 阈值陷阱）。
