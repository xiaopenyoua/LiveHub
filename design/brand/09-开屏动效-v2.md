# 开屏动效 v2 · 要不要动效，以及不动的时候动什么

> 版本 **v2.2** · 2026-10-29 · 裁决人：Apple Style Designer
> **v2.2 变更（不新增章节）**：① 卡面色值结案——**开屏那一帧没有卡片，整屏 `#1A140F`**（主理人裁定，见 `08` §4「新裁决」），§6 由条件句改事实句、§10 第 5 条结案；② §2 约束 2 与 §3 首帧按"没有边界"重写，理由更强；③ §6.1 与 §10 第 1 条改称「**唯一机制**」；④ B=1980 获批准，数字未动。

## 0. 结论先行

| 项 | 裁决 | 一句话理由 |
| --- | --- | --- |
| 要不要动效 | **方 1 · 零动效，首帧即定稿** | v2 没有能承载动效的对象；动效也治不了 v2 真正的病（等待中段） |
| 首帧 | **整屏 `#1A140F` 与字标两色都在终值**，不淡入、不缩放 | 规则从「P0 alpha=1」升级为「**P0 帧里最亮的对象已在终值**」 |
| 等待 | **最短驻留 400ms**，静止，一动不动 | 少于 400ms 的整屏画面读作一次闪，不读作一幅画面 |
| 退场 | 只淡**墨**（字标 + 若在的异常行）200ms；**墨归零那一帧整层销毁，画面零变化** | 整屏同色、卡面无边界，撤层不需要淡——淡反而会在大面积上生成 banding |
| 死机感 | **靠时间上限 + 异常才出的那一行信息**，不靠动画 | 动效只在前 200ms 有效；用户怀疑死机发生在 900ms 之后 |
| 红线 | **A 上限 1700ms**（v1 是 1900）；B 上限 1980ms | 入场四段接力取消，省掉的 200ms 是真省；B 涨的 200ms 付在"开屏已不可见"之后 |
| 两处字标 | **零交叠不够，还要 ≥200ms 全屏无字标**：开屏字标归零（A）后再等 200ms，顶栏字标才起（T+400 → T+480） | 顶栏那枚已由用户裁定保留，v2 又是同形同色两份拷贝——**这 200ms 是唯一那道闸**，不是补充约束 |
| 正常路径 | **不出现任何"状态"**；只有实测 P90 > 900ms 时，那一行才提前到 1000ms | 提示要卡在"用户开始怀疑"之前，不是"失败"之后 |

## 1. 判决：零动效，这是设计不是省略
三条理由，一条比一条硬。

**① v2 没有能承载动效的对象。** 整屏只有一样东西看得见：**一行双色字标**。1440×810 是版面框，卡面与底同值、**没有边界**（§10 第 5 条已结案）。所以方 2 提的「卡片 scale 0.97→1」在 v2 里不成立为"卡片在落定"——缩放的是一块看不见的框，**屏上唯一会动的就是字标本身**：1131.84px 宽的字标缩到 0.97 是 1097.88，两侧各内收 **17px（3 米外 12.4 弧分）**，而且每一帧的字距都是错的。那不是"微妙的落定"，是字在自己呼吸。能动字的只有 alpha——而**品牌字标只有一个正确形态，动画经过的每个中间态都是错的品牌**（04 §6 第 5 条，这条在 v2 里比在 v1 里更不容辩）。

**② 动效治不了 v2 真正的病。** v2 的死机感不在开场，在**等待中段**：结论 900ms、超时 1500ms，这段屏幕完全静止。任何开场动效都在前 200ms 内结束，对 900ms 之后毫无帮助。为一个它治不了的病吃一次 OLED 风险，不划算。v1 之所以敢让屏幕静止 960–1500ms，是因为它有**四行真实状态**在说话；v2 把状态行拿掉了，**治法就必须换成"时间上限 + 异常才出现的真信息"**，而不是补一段动画。

**③ 用户那句话本身是反对动效的。** 「首屏就相当于图标的放大版」——**放大版是一个状态，不是一次放大动作**。做一次 scale 反而不像"放大版"，像"正在长出来"；而"正在长出来"会被读成"还在准备"，这正是 04 §4 判过的「启动两次」。**越是想让人相信"这就是那个图标被放大了"，就越不能让它动。**

**反证（我认真验过并否掉的那条）**：能不能让卡片从系统图标的 192px 一路长大到 1440px，把段 1→段 2 的接缝彻底抹平？不能。那是 **7.5 倍**的缩放，中途经过的每一个尺寸都不是品牌，也没有任何一帧等于"图标的放大版"；而且 1440 宽的面在放大时，字标必须同步缩放——文字缩放的每一帧都是错的字距。**接缝不许用动画补，只能靠落点整齐来救（§3）。**

## 2. 三个硬约束，我逐条判了（其中一条要改您的理由）
**约束 1「整层淡入是空操作」——结论对，理由要换。** 从 #000000（L\* 0）到 #1A140F（L\* 6.8），ΔL\* 6.8 **不是看不见**：在暗室里，大场面的 JND 约 1 L\*，6.8 是可察的。真正的理由不是"看不见"，是**它会在大面积上生成 banding**——8bit 下这段只有 26 个 R 码值，300ms 摊 18 帧等于每帧 1.4 个码值，一块近黑的大平面会浮出等值线。**所以不许淡的不是"因为看不出来"，是"因为看出来的是层次断层"。**

**约束 2「卡片边界 1.09:1 不能当动效主线索」——账已结：这条边界在 v2 开屏里不存在，所以它不是"不能用"，是"没有"。** 先把数字说清（以后还会被人拿去当依据）：WCAG 的 1.086:1 是低亮度区被压缩过的比值，换算成 ΔL\* 是 **4.1**、Y 的 Weber 比 **65%**——在暗室里它是看得见的，只是低对比；而 4.1 个 L\* 只有约 6 个码值的余量，任何漂移都会断层。但按 `08` §4「新裁决」，**应用开屏与应用内同为 `#1A140F`，开屏那一帧没有卡片**。于是这条约束从"低对比的边界不能承载动效"升级为**"没有这条边界可动"**——比原判更硬：不是不敢用，是没有。**连带的正面结论**：既然屏上只有字标可见，"能动什么"就只剩一个答案——只能动字；而字不许动（①），所以整案没有可动之物。

**约束 3「首帧不能从 0 起」——结论不反转，但规则要说得更准。** v1 的原话是「P0 那一帧图标必须 alpha 1」，那是针对**图标**说的。换成一条能同时管 v1 和 v2 的判据：**P0 这一帧，屏幕上最亮的那个对象必须已经在终值。** v1 里最亮的是图标（白三角，21:1）；v2 里最亮的**只有字标**（白 `Live`，对 L\*6.8 约 18:1）。所以 v2 的 P0 铁律不是"整层不许淡入"，而是——**字标必须在第一帧就亮到位**。若允许底先淡、字标后到，最亮对象就成了"正在变亮的东西"，那正是 v1 判过的"屏幕在渐亮 = 还在准备"。这条比原话更严：它顺手封掉了"底淡入 300ms、字标 200ms 后跟上"这种看似讲究的做法。

## 3. 首帧三条铁律
1. **P0 即定稿**：整屏 `#1A140F`（L\* 6.81），字标两色均 100%、落在 1440×810 版面框内——**字标 311.85px，cap 顶 291.58 / baseline 518.42**（几何归 UI 07 C 档）。没有任何属性从 0 或从"小一点"起。
2. **首帧必须已经包含字标**——不是"卡片先出来、字标随后补上"。后补会让首帧变成"一个还在画的屏"，而用户对"还在画"的耐心只有几百毫秒。
3. **接缝的诚实**：段 1（系统帧，`#231C16`，192dp 图标居中）与段 2（我们，`#1A140F`，1440×810 版面框居中）**同心，但既不同底也不同尺寸**——底差 ΔL\* 4.08（`08` 判合法，**全案只此一次**），尺寸差 7.5 倍。这一次跳变无法隐藏，只能让它跳得干净：从"一个居中的东西"到"一个更大的、居中的、已经完成的东西"。**能控制的是落点整不整，不能控制的是它跳不跳。**

## 4. 时间刻度：A/B 双轨，数值重算
`T` = homeFeed 给出可用结论（`Loaded`）的时刻，且 **T ≥ 400ms**（最短驻留，见 §5）。T 的上限是 site 层 **1500ms** 超时——它保证 1500 之前必有结论，但结论可能是 `Failed`（那就出异常行，不退出，§7）。

- **A · 开屏不可见** = 墨淡出走完、整层销毁（T+200）
- **B · 屏上再没有任何元素在动** = 顶栏字标收尾（T+480 = A + 200 空白 + 80 淡入）

| 路径 | 结论 | T | **A** | 空白 [A, A+200] | **B** |
| --- | --- | --- | --- | --- | --- |
| 最快（缓存命中） | ≤ 400ms | **400**（驻留下限） | **600** | 600 → 800 | **880** |
| 典型 | 1200ms | 1200 | 1400 | 1400 → 1600 | **1680** |
| 上限 | 1500ms | 1500 | **1700** | 1700 → 1900 | **1980** |
| 失败 | 1500ms `Failed` | — | **不退出**，出异常行（§7） | 无 | 同左 |

**A 的上限 1700，比 v1 的 1900 少 200ms，这不是四舍五入——是结构简化直接退回来的预算。** v1 的 200ms 是「P4 一次翻转被看见」的确认余量（结论到了要给它 200ms 让观众看见它变了）；v2 没有状态行，就没有"一次翻转"这件事，那 200ms 无处可花，也就不该花。

**B 从 1780 涨到 1980，这 200ms 是 §6.1 那条空白的直接算术结果，不是新预算。** 它付在"开屏已经销毁、屏幕已经归位、只差一个 30px 字标"的那一侧——**用户感知到的"开屏结束"仍然是 A，红线仍然按 A 判。** 顺带一个巧合要说清：v2 的 B 上限与 v1 的 B 上限都是 1980，但两条账不同——v1 多付一次 200ms 的 P4 确认，v2 多付一次 200ms 的字标空白，两者都不能省。

**对外沟通、设计稿标注、前端断言一律用 B；红线按 A 判。**

## 5. 最短驻留 400ms：防的是"闪一下"
homeFeed 命中缓存时可能 80ms 就回来。若照 80ms 就撤，观众看到的是"一整屏闪了一下"——**整屏画面短于 ~400ms 不读作一幅画面，读作一次闪烁**，而闪烁恰好落在启动的第一秒，最容易被解释成故障。3 米处一次注视约 200ms，加"这是一幅画"的读解，取 2 倍即 400。代价：缓存命中时白等 320ms。**这 320ms 买的是"没闪"，比省它值。**

**此条已裁，不再议**：静止不是代价，闪才是代价；40ms 内消失的 logo 读作失败。400ms 是"我确实看清了一眼"的下限——而 v1 的同类下限是 960ms，**v2 已经比它克制 2.4 倍**，不该再往下压。剩下的只是工程把它写进代码（见 §10 第 3 条）。

## 6. 退场：淡的是墨，不是卡
- **只有墨淡出 200ms**，`cubic-bezier(.4,0,1,1)`；**底与版面框全程不动**，墨归零那一帧整层销毁。**"墨"= 字标 +（若在）§7 那一行**，两者同曲线、同 200ms 窗口——这样才能保证销毁那一帧屏上真的一滴墨都不剩，异常行不会在撤层时 pop 一下。
- 为什么淡 200 而不是硬切：字标是屏上唯一的高亮对象（18:1），一帧消失是**一次局部阶跃**，读作故障；200ms 内与首页内容的 240ms 淡入并行，屏幕亮度单调上升，**没有一帧是 0 nit**。
- **为什么不存在"卡片淡出"这件事**：开屏那一帧**没有卡片**——应用开屏与应用内同为 `#1A140F`（`08` §4「新裁决」已结案），卡面与根层同值，**撤层时画面零变化**（03 §9 第一条的机制，v2 继续沿用）。所以"卡片不淡"不是一个需要执行的纪律，是一个**不需要执行的事实**。谁要把卡片重新引进来（`#231C16` 浮在 `#1A140F` 上），先看 `08` §4 ②「两底色不得同帧」与 §5「同画面相邻面 ΔL\* ≥ 8」——那是另一个方案，退场也要重做。
- **首页内容必须先合成在位**（规范 §10 的加载态：纯色 + 平台名，不闪光不骨架跳）。否则开屏做得再对，也会被首页第一帧打回。
### 6.1 两处字标：零交叠不够，还要 200ms 空白（已裁）
- **顶栏那枚 30px 字标由用户明确指令保留**（原话「首页顶栏现在那个 30px 的 LiveHub 字标保持现状」），所以"删掉它"这条路已经关闭。它的起点**锁在 A 之后**：**T+400 起、80ms 到 1（T+480）**。
- **为什么"零交叠"不够**：v1 有两层保护——零交叠，以及 **120 与 30 两个尺寸分得开**。v2 **同形同色两份拷贝**，尺寸那层保护没了，**"零交叠"独木难支**。两个同形刺激的间隔（ISI）**在约 200ms 以内，视觉系统会自动把它们连成同一个物体的运动轨迹**——这是 apparent motion 的上界。所以只要顶栏字标在开屏字标消失后 200ms 内出现，**哪怕一帧都不重叠**，看到的仍然是"那个大标志缩小飞到了左上角"。
- **因此这 200ms 是唯一那道闸，不是补充约束**：开屏字标归零之后，必须 **≥200ms 屏上没有任何字标**，顶栏字标才起。200 是这个阈值的边界值，**不是余量**；它已经是下限，取更大只会把 B 继续往后推（§4）。**删掉这条，v2 就没有第二道防线了。**
- **代价（写明）**：T+200 起首页已完整可见，但顶栏左端空着 200ms。**这个空白是设计**——它让"品牌最后一个归位"读作落定，而不是"导航栏少了一块"。前提是页签位置**一帧都不许动**。
- **空白的第二前提**：首页首屏不得有第二处 `LiveHub` 字样（含加载态、空状态文案）。空白一旦被别处的字标填上，这 200ms 就白花。
- **实施纪律**：只挂 `graphicsLayer{alpha}`、**归零不摘除**——摘除会让 `Row` 宽度塌陷、页签左移 ≥8px，那不是淡入，是一次硬切。

## 7. 唯一允许出现的动效：异常那一行
正常路径**什么都不会出现**，这是刻意的：唯一诚实的"我还活着"信号是**真信息**，而 v2 正常路径上没有任何真信息可显示（四家状态已被裁掉）。
- **触发（两种配置，按实测选，选定即执行，不需要再裁）**：
  - **默认**：site 层 1500ms 超时且无可用结论 → 出失败行。正常路径永不出现。
  - **若实测 P90 结论时刻 > 900ms**：出现时刻**提前到 1000ms**。此刻还没有失败，所以它**不能说"失败"**——只说此刻为真的话：「还在连」。1500ms 到了仍无结论，**同一行 80ms 内换成失败文案**，中途不删不重建。
- **为什么是 1000**：提示要卡在**用户开始怀疑**之前，不是**失败**之后。静止的屏幕在 900ms 附近开始被读成卡顿，1000ms 就在那条线前面一点。更本质的一条：**正常路径上用户永远看不到任何"状态"**——这才是 v2 敢把状态行全裁掉的理由。
- **为什么不违禁**：一句话不携带任何伪造的量化（没有百分比、没有进度条、不脉动、不转圈），且它在显示期间**始终为真**。04 §6 禁的是假进度，不是真陈述。
- **不许推动任何东西**：这行从版面框下方的既有空白里出现，**不需要预留槽位**（1440×810 的版面框里只有一行字标，下方是空的）。判据是硬的：出现前后，**字标的包围盒一个像素都不许变**——出现只能是 alpha。
- **形态**：一行 22px（`--fs-meta`），灰阶（`#B4B4B4` / `#8E8E93`），**不用红**——红在 v2 开屏只有 `Hub` 一处合法。文案判据沿用 03 §6：系统网络决定写「电视没有连上网」还是「四家平台都没连上」。
- **出现方式**：**80ms alpha**。不做 0ms 的 pop（pop 读作"坏了"），也不做 200ms（那是层的时长，一句话没那么重）。80ms 是"一次出现不成为一次闪烁"的下限，与顶栏字标同一条纪律。
- **出现之后**：不自动消失、不自动重试、不脉动、不加 spinner。屏幕重新回到完全静止。**重试只由用户按键触发**；若有重试入口，其出现与这行同步，方式相同。

## 9. reduced-motion
| 元素 | 替代 | 时长 |
| --- | --- | --- |
| 开屏段（整屏底、字标） | 本来就没有入场动效，**无可压缩** | 0 |
| 字标淡出（A 刻度） | 1 帧 | 16ms |
| 顶栏字标（B 刻度） | **单独再 1 帧，顺序不可省** | 16ms |
| 两处字标之间的空白 | **不压缩**（它是结构，不是过程） | 200ms |
| 异常行 | 1 帧 | 16ms |
| 整层销毁 | 与字标那帧同帧 | 0 |

过渡合成 **32ms**；另加**不压缩的 200ms 空白**，共 232ms。开屏段的 400ms 驻留下限**不变**（它是信息时长，不是动画时长）。v1 那句「压时长、不删 transform」在 v2 里退化成一句更简单的话：**v2 没有任何 transform，所以没有可删的东西；要守的只剩"顺序与间隔"**——两处字标的先后不能压进同一帧，**它们之间的 200ms 也不能压**：压的是过渡，不是间隔，把间隔压掉就是把结构删了。判据照旧读 `Settings.Global.ANIMATOR_DURATION_SCALE == 0`。

## 10. 冲突提示
1. **两处字标（已裁，且这是唯一机制）**：用户已明确指令顶栏那枚 30px 字标**保持现状**，所以它一定在；它前面必须有 **≥200ms 全屏无字标的空白**（§6.1），起点 T+400、B 上限 1980。**v1 靠"零交叠 + 120/30 两个尺寸"双保险，v2 是同形同色两份拷贝，只剩这一道闸。** 它也最容易被"v2 已经没有动效了"顺手删掉——它不是动效，是内容间隔。
2. **1.09:1 与 4.1 ΔL\* 的口径**：这条针对的是**图标/系统帧那一处的 4.08**，不是开屏（开屏没有卡片）。它会影响下一个人的推理——若有人拿"1.09:1 看不见"当依据去加描边或加阴影"把卡片托起来"，那就越过了规范 §2 的禁线。**那 4.08 是设计，不是缺陷；觉得不够，抬亮度差，不加线。**
3. **驻留下限 400ms 已裁，剩下的是工程**：它要求"结论早于 400ms 也要等"，这是一次显式的 delay。**产品不必再议**，但它必须写进代码并被断言——否则它会在第一次"顺手的性能优化"里被删掉，而删掉之后现场表现是"开屏闪一下"，没人会把它归因到这次改动。
4. **前端断言的数字变了**：v1 的四个数（960/1500/1700/1900）不适用 v2。v2 只有 **A 上限 1700、B 上限 1980**，外加 T 的下限 400 与上限 1500。断言若还按 1780 写，会在弱网现场误报通过。
5. **卡面色值归属（已结案）**：`08` §4 的底色链是「应用开屏 + 应用内 = `#1A140F`」，与「卡面 L\* 10.9 / Δ4.08 / 1.09:1」那一版口径不能同时成立（`08` §4 ②「两底色不得同帧」、§5「同画面相邻面 ΔL\* ≥ 8」都判后者违规）。**`08` §4「新裁决」裁定：开屏那一帧没有卡片，整屏 `#1A140F`。故只有前一种成立，§6 退场设计维持不变，本文至此无开放项。** 留一条判据给后来者：**若有人在应用帧里重新引入 `#231C16` 卡面，那不是调色，是换了方案**——退场要连同 §6 一起重做。

## 11. 判定
**Ships as Apple-style：yes-with-fixes。** 「零动效 + 首帧即定稿 + 异常才出信息」是 tvOS 式克制的正解，也是用户那句"放大版"的字面兑现。

**代价，一次列清（三条，都要认）**：缓存命中时白等 320ms（§5）；顶栏左端空 200ms（§6.1）；B 从 1780 推到 1980（§4）。三条都不是为了让开屏好看，是为了让"没闪"和"不是一个标志飞过去"这两件事成立。

**最大风险不在动效，在静止的长度**：v2 把 v1 唯一的"活着的证据"（四行真状态）拿掉了，代价就是等待中段可以被读成死机，而这段长度由网络决定、不由设计决定。**唯一的解是让等待有上限、并且超时就出真话**——这一条若被当成"可以以后再说"，v2 的开屏会在弱网现场被打回，且回不到动画上。
