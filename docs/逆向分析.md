# 逆向分析报告：纯粹直播 v1.7.4 的直播功能是怎么搭起来的

> 分析对象：`示例参考软件.apk`（167,927,123 字节，SHA-256 `4834bec9…81e95f`）
> 方法：REA（`inspect_dart_aot`，证据 `ev_904e175c1b7d2c21…` / 视图 `ev_821357b9b232a2e7…`）+ aapt2 清单解包 + Dart AOT 字符串池 + 资源清单 + 上游开源实现交叉验证 + 四家接口实测
> 结论分三级：**观测**（能在产物里指到字节/文件）、**推断**（由结构推得，未直接看到代码）、**未知**

---

## 一、这是个什么应用（观测）

| 项 | 值 | 来源 |
| --- | --- | --- |
| 包名 | `com.mystyle.purelive` | aapt2 badging |
| 版本 | 1.7.4 (versionCode 1) | 同上 |
| minSdk / targetSdk / compileSdk | 21 / 31 / 34 | 同上 |
| 运行时 | Flutter（Dart AOT，`lib/arm64-v8a/libapp.so` 9.4 MB） | `inspect_dart_aot` |
| 应用自有代码包 | `package:pure_live/*`，124 个 Dart 模块 | AOT 字符串池 |
| 动态签名能力 | `libfastdev_quickjs_runtime.so` + `assets/js/webmssdk.js` | 文件清单 |
| 播放内核 | `libmpv.so`(11.9 MB)、`libvlc.so`(42.6 MB)、`libijkplayer/libijkffmpeg`、`libsaasCorePlayer`(阿里云)、`libalivcffmpeg`、`librtmp-jni` | 文件清单 |
| 云端 | Supabase（`assets/keystore/supabase.json`，含 anon key） | 资源文件 |

**为什么是 Flutter：** `libapp.so` 里能导出 `_kDartVmSnapshotData` / `_kDartIsolateSnapshotData` 两段 magic=3 的快照（Dart 2.14 FullAOT 布局），`package:pure_live/...` 与 `package:flutter/...` 的 URI 直接暴露了模块边界。这不是靠文件名猜的。

**一个容易忽略的事实：** 它是 Flutter 应用，但界面的相当一部分靠内嵌的 Flutter **Web 构建**跑在 WebView 里（`assets/flutter_assets/assets/pure_live_web/main.dart.js`，1.7 MB，带 canvaskit）。也就是说它把「跨端复用」做在了 UI 层——同一套 Dart 代码编译成 Web 再塞回 App。这条路我们不走（TV 端 WebView 的遥控器焦点和硬解都不划算），但它解释了为什么 `main.dart.js` 里几乎没有业务 URL——业务在 AOT 里，Web 壳只负责渲染。

## 二、功能是怎么分层的（观测：模块名即架构）

Dart 包里的目录结构几乎就是一份架构文档：

```
core/interface/live_site.dart        ← 平台取数接口
core/site/{bilibili,douyu,huya,douyin,kuaishou,cc,iptv}_site.dart
core/interface/live_danmaku.dart     ← 弹幕接口
core/danmaku/{bilibili,douyu,huya,douyin}_danmaku.dart
core/danmaku/proto/douyin.pb.dart    ← 抖音弹幕 protobuf
core/common/{http_client,custom_interceptor,web_socket_util}
core/iptv/src/m3u_*.dart             ← 还支持 m3u 直播源
modules/live_play/{live_play_page,video_player/danmu_merge}
plugins/barrage.dart                 ← 弹幕渲染
```

三条判断：

1. **平台是插件化的。** 七个 site 实现同一个 `live_site` 接口，连 IPTV（m3u 播放列表）都当成一个「平台」接进去。新增一家平台只写一个文件。
2. **弹幕与取流彻底解耦。** `live_danmaku` 与 `live_site` 是两套接口，抖音弹幕单独带 protobuf 生成代码。这解释了为什么它能在「取流失败」时仍然显示弹幕。
3. **播放器是三个内核并存**（mpv / VLC / IJK+阿里云），`modules/live_play/widgets/video_player/video_controller.dart` 是那层切换器。这不是技术炫技——是**兼容性兜底**：老盒子的 MediaCodec 解不了部分 FLV/H.265，只能靠软解内核。

### 对我们项目的直接含义

- 我们的 `core/site/LiveSite.kt`、`core/danmaku/DanmakuClient.kt` 就是照这个切法定的接口（6 个取数方法 + 1 个冷流）。
- 它用三个内核，我们第一版只用 Media3。这是**已知差距**，见第七节。

## 三、四家平台的取流链路（观测 + 实测）

AOT 字符串池里能直接读到接口地址，四家的路径如下（`strings libapp.so | grep https://`，已去重）：

| 平台 | 房间/列表 | 播放地址 | 弹幕 |
| --- | --- | --- | --- |
| 哔哩哔哩 | `api.live.bilibili.com/room/v1/Room/room_init`、`/xlive/web-interface/v1/second/getListByArea`、`/room/v1/Area/getList` | `/xlive/web-room/v2/index/getRoomPlayInfo` | `/xlive/web-room/v1/index/getDanmuInfo`、`broadcastlv.chat.bilibili.com` |
| 斗鱼 | `www.douyu.com/betard/{rid}`、`/gapi/rkc/directory/mixList/2_{cate}`、`/japi/weblist/apinc/getC2List` | `/lapi/live/getH5Play/{rid}`、`/swf_api/homeH5Enc?rids=`、`alive.nsapps.cn/api/AllLive/DouyuSign` | `danmuproxy.douyu.com:8506` |
| 虎牙 | `mp.huya.com/cache.php?m=Live&do=profileRoom&roomid=`、`live.cdn.huya.com/liveconfig/game/bussLive` | 同上接口的 `sFlvUrl` + `sFlvAntiCode` | `cdnws.api.huya.com` |
| 抖音 | `live.douyin.com/webcast/room/web/enter/`、`/webcast/web/partition/detail/room/` | 同上接口返回的 `stream_url` | `webcast3-ws-web-lq.douyin.com/webcast/im/push/v2/` |

**本次实测（2026-10-29，本机直连）：**

| 平台 | 请求 | 结果 |
| --- | --- | --- |
| 哔哩 | `room_init?id=21452505` | `code:0, live_status:1`，拿到真实房间号 |
| 哔哩 | `getRoomPlayInfo(room_id=21452505, qn=10000, platform=h5)` | `code:0`，flv / ts / fmp4 三种格式各 2 条线路；未登录时 `current_qn=250`，`accept_qn=[10000,400,250]` |
| 斗鱼 | `hlsH5Preview/9999`（`auth=md5(rid+毫秒时间戳)`） | `error:0`，返回 `rtmp_url=https://hlshwa.douyucdn2.cn/live` + `rtmp_live=9999rMfVyoBTjV0x.m3u8?txSecret=…` |
| 虎牙 | `profileRoom&roomid=660000&showSecret=1` | `sStreamName` + `sFlvUrl` + `sFlvAntiCode`（**wsSecret 已算好**，不必自己 md5） |
| 虎牙 | 拼出的 FLV 地址 `Range: 0-2047` | **HTTP 200，返回 531,999 字节**，可播 |

### 三个关键判断

1. **斗鱼不必啃签名 JS。** 它同时保留了 `getH5Play`（要跑 `ub98484234` 混淆 JS 算 sign）和 `hlsH5Preview`（只要 `md5(rid+时间戳)`）。后者是给「预览」用的，权限低但够播，**取流成本从「内嵌 JS 引擎」降到一次 md5**。这是本次逆向最有价值的一条。
2. **虎牙把 anti-code 直接算好了。** `sFlvAntiCode` 里 `wsSecret` 已经是最终值，客户端只要拼接。网上很多实现还在自己 `md5(prefix_uid_stream_seqid_now_wsTime)`，其实是为老接口准备的。
3. **哔哩未登录拿不到原画。** 实测 `current_qn` 被压到 250（超清），要原画必须带 `SESSDATA` 登录态。这直接决定了我们播放页的「清晰度」胶囊在未登录时只能显示到 1080P，而且**不能撒谎**——这条已经写进设计规范第三节。

## 四、弹幕：四套协议，四种难度（观测 + 推断）

| 平台 | 传输 | 编码 | 难度 | 依据 |
| --- | --- | --- | --- | --- |
| 哔哩哔哩 | WSS `/sub` | 16 字节头 + JSON，protover=2 时 zlib 压缩 | 低 | `blivedm` 同构；AOT 含 `getDanmuInfo`、`broadcastlv` |
| 斗鱼 | WSS `:8506` | STT：`[4B 长度][4B 长度][4B 689][key@=value/…]` | 低 | 依赖 `binary_writer.dart` / `convert_helper.dart` |
| 虎牙 | WSS `wsapi.huya.com`（旧版为 `cdnws`） | **Tars**（命令 16 注册组、20 心跳、push type 7/22） | 中高 | 依赖 `dart_tars_protocol` |
| 抖音 | WSS `webcast…/im/push/v2/` | **protobuf**（PushFrame/Response/Message） | 高 | 依赖 `protobuf` + `proto/douyin.pb.dart` |

**抖音还有第二道门：签名。** `live.douyin.com/webcast/room/web/enter/` 要求 `a_bogus`/`X-Bogus`，应用的做法是：

1. 打包 `assets/js/webmssdk.js`（58 万字节，文件头自述 *"extracted from douyin webmssdk.es5.js, Modified by @hua0512, 2024-06-21"*）；
2. 用 `libfastdev_quickjs_runtime.so`（QuickJS）在原生侧执行它；
3. 脚本末尾留的入口就是证据：

```js
function get_sign(md5) {
    let data = { 'X-MS-STUB': md5 }
    return crawler(data)['X-Bogus']
}
```

也就是说：**抖音的签名不是算法，是一段必须被 JS 引擎执行的黑盒**。想绕开只能换接口或换入口。

## 五、抖音这条线的三条路（推断 + 建议）

| 路线 | 做法 | 成本 | 稳定性 | 我们的选择 |
| --- | --- | --- | --- | --- |
| ① 免签 mobile 接口 | `webcast.amemv.com/webcast/room/reflow/info/?app_id=1128&room_id={19位}` | 极低（一个 GET） | 中（接口多年未改，但只覆盖「已知 room_id」） | **第一版采用** |
| ② WebView 跑 webmssdk.js | 隐藏 WebView 载入脚本，`evaluateJavascript` 取 X-Bogus | 中（要处理 WebView 冷启动、脚本体积、TV 端 WebView 版本差异） | 中高（跟官方脚本同源） | 第二版 |
| ③ 服务端代签 | 自建服务跑 acrawler 或无头浏览器 | 高（要运维，且把风险集中到自己身上） | 高 | 不做 |

第一版选 ①，代价写在明处：抖音的**推荐流与搜索**（`live.douyin.com/webcast/web/partition/detail/room/`、`/aweme/v1/web/live/search/`）都要签名，所以这两个入口在首版是「空列表 + 一行说明」，只有「按房间号直达」可用。**不伪造数据**是底线。

## 六、它没做、我们也不该做的

- **没有跨平台统一台号。** 它用 `platform + roomId` 二元组定位房间（`LiveRoom` 模型）。我们沿用了这个决定，并在设计文档里明确「房间号就是房间号」。
- **没有多用户档案。** 关注列表是单份的，一家人共用一台电视会混在一起。
- **弹幕不走独立服务。** 每家一个 WSS 直连，没有中间层，所以也没有「弹幕审核」能力——这在合规上是它回避的问题。

## 七、已知差距与风险（诚实清单）

| 项 | 它 | 我们（第一版） | 影响 |
| --- | --- | --- | --- |
| 播放内核 | mpv / VLC / IJK+阿里云，可切 | Media3（ExoPlayer） | 部分老盒子 FLV/H.265 可能解不了；已留 `decoderMode` 设置位与可读错误提示 |
| 抖音推荐/搜索 | 有（靠 QuickJS 签名） | 无（免签接口只覆盖房间号直达） | 抖音只能「知道房间号才看得到」 |
| 虎牙弹幕 | Tars 完整实现 | 见 `HuyaDanmaku.kt` 实现说明 | 若 Tars 解码不全，只影响弹幕不影响播放 |
| 云端同步 | Supabase | 本地 SharedPreferences | 换设备关注列表不同步 |
| IPTV / m3u | 支持 | 不支持 | 超出「四平台聚合」范围 |
| 登录 | 哔哩扫码登录 | 未做 | 哔哩清晰度上限 1080P |

## 八、这套结论落到代码的哪里

| 逆向结论 | 我们的实现 |
| --- | --- |
| `live_site` 六方法接口 | `core/site/LiveSite.kt`，四个实现各一文件 |
| `live_danmaku` 冷流接口 | `core/danmaku/DanmakuClient.kt` + 四个客户端 |
| 斗鱼免签取流 | `DouyuSite.playUrls()` 走 `hlsH5Preview` |
| 虎牙 anti-code 已给 | `HuyaSite.playUrls()` 直接拼 `sFlvAntiCode` |
| 哔哩 qn 上限受登录影响 | `BilibiliSite.playUrls()` 读 `accept_qn` 与 `current_qn`，把真实值写进 `PlayUrl.quality` |
| 三内核兜底的必要性 | `LivePlayer` 把内核隔离在一层之后，UI 不知道 ExoPlayer 存在 |
| 抖音签名是黑盒 | 首版走免签接口，第二版再上 WebView |

## 九、还没搞清楚的（未知）

1. **虎牙新版 Tars 的完整字段表。** `wsapi.huya.com` 的 push 结构体（`HYMessage` 的 content/userInfo/bulletFormat 各在哪个 tag）来自 pub 包 `dart_tars_protocol`，本机未取到该包源码，只能靠实际抓包反推。抓包不通时，虎牙弹幕降级为「连接成功但不显示内容」，并用一条系统提示说明。
2. **抖音 19 位 room_id 与 web_rid 的映射规则。** 首版要求用户输入 19 位 ID 或完整分享链接，不做 web_rid 反查（反查接口要签名）。
3. **`alive.nsapps.cn/api/AllLive/DouyuSign` 这个第三方签名服务是谁在维护。** 应用里出现了它，但我们不依赖第三方中转——这条链路一旦挂，用户数据会经过陌生服务器。
