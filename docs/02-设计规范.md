# LiveHub 设计规范

> 版本 v1.0 · 2026-10-29
> 适用：Android TV 1920×1080（按 4K 等比放大）
> 设计语言：Apple tvOS 的骨架（内容优先、焦点驱动、极简控件）＋ 深炭灰底 + 中央暖金光晕 + 烟色磨砂玻璃

---

## 一、核心概念：没有台号，只有房间号

早期版本虚构过一套「跨平台三位台号」：哔哩 1xx、斗鱼 2xx、虎牙 3xx、抖音 4xx，数字键三位直达。**这套东西在 2026-10-29 被推翻了**——直播没有台号这个说法，四个平台的编号体系彼此不兼容，也从来没有一家做过跨平台统一编号。虚构编号不只是「不准确」，它会连带污染搜索（要造「台号匹配」的排名）、换台（要拿编号当大字）、分类（要造号段菜单）三个地方。

**四个平台真实的房间标识**

| 平台 | 叫什么 | 形态 | 说明 |
| --- | --- | --- | --- |
| 斗鱼 | 房间号 | 纯数字，4–8 位 | 网址末尾那串就是。大主播有 4 位短号（`9999`），普通主播 7–8 位。房间号唯一，输房间号是最精准的找法 |
| 虎牙 | 房间号 | 纯数字，最多 8 位 | 2018-04-12 起系统随机发放、不可自选，与 YY 号、频道号无关。官方：「用户通过房间号搜索，默认会优先展示该房间号对应的直播间」 |
| 哔哩哔哩 | 两套 | 短号（可无）+ 8–10 位真实房间号 | 主播自选 `short_id`，没有时为 `0`；系统分配 `room_id`。地址栏显示短号，但大部分接口只认真实房间号，需 `room_init` 转换 |
| 抖音 | 无固定房间号 | v1 寻址：**房间号（19 位 room_id 或 6–12 位 `web_rid`）或直播页链接**；抖音号只作展示 | `live.douyin.com/<数字>` 那串是 `web_rid`，**不是**内部 19 位 room id；`web_rid → room_id` 靠抓直播间页 HTML 里 `roomId` 与 `web_rid` 配对换算，免签、v1 能做。抖音号（`xiaojiuguan` 这类自定义字符串）反查要签名，v1 做不到，见下方工程约束 |

**工程约束（v1，来自 `04-Android架构.md` §4.1）**：抖音在 v1 靠 **房间号或直播页链接**寻址——输入框接受三种写法（19 位 room_id、6–12 位 `web_rid`、`live.douyin.com/...` 整条链接），归一化在 `DouyinSite` 内部完成，**UI 不做解析**；卡片与播放页**照常显示抖音号**（显示的是数据），但"输入抖音号直达"这条能力 v1 没有，要等签名接入（v2）。文案要求：输抖音号无结果时写「抖音请粘贴直播页链接或房间号」，不写「未找到」。抖音也不参与关键词搜索（`capabilities.search = false`），理由同上。**占位提示不要写"19 位"**——用户不会去数位数。

**数据模型**

一条直播只存它自己平台那套，不转换、不映射、不排名：

```js
{ rid:'660000', kind:'room', p:'huya', ... }   // 虎牙房间号
{ rid:'xiaojiuguan', kind:'dyid', p:'dy', ... } // 抖音号
```

- `rid` 是字符串，比对一律 `r.rid === String(input)`，**永远不 `Number()`**。转数字会把「抖音号是字母」和「房间号前导零」两种台账直接打乱。
- `kind` 决定界面写「房间号」还是「抖音号」。抖音没有房间号，硬写三个字就是错的。
- 凡界面上露出来的字符，都必须是屏上键盘打得出来的。抖音号允许下划线，数据里就避开了——没有下划线键，带了等于藏起来。
- 换台顺序按数组的编辑顺序，不按编号排序：房间号长度不一，还混着字母串，排序没有意义。

**因此删掉的东西**

| 删掉的 | 原因 |
| --- | --- |
| 卡片左上角的三位台号 | 改为**平台名**。8 位数字塞不进药丸，一排卡片立刻参差；而聚合客户端里这一格最该回答「这是哪个平台的」 |
| 换台条 120px 大字台号 | 改为**主播名**。6–10 位数字 120px 一行放不下；换台时人想确认的是「下一台是谁」 |
| 分类左栏号段（100–199…） | 改为**该平台在播数量**。对比「哪家内容多」比对比不存在的编号有用 |
| 数字键三位直达 | 真实房间号 4–10 位、抖音号是字母串，遥控器数字键没有回显，盲打错一位就跳错台且无声无息。找台走搜索 |
| 搜索的「123 / ABC」模式切换 | 见第八章。数字和字母同一块键盘，没有第二种搜索方式 |

**替代方案是什么**：搜索。输入框看得见、边打边筛、按「完全相等 > 前缀 > 包含」排序。直播间标识不再是导航手段，而是校验手段——「我搜到的这个是不是刚才那个台」。

## 二、色彩

三个决定，缺一层都不成立：**低饱和深炭灰的底** + **中央一层柔和弥散的暖金光晕** + **烟色玻璃的面**。

底是中性偏冷的炭灰（R < B），冷的部分交给光晕去中和 —— 底色负责"沉"，光负责"暖"，两件事分开。玻璃压在上面时，才会透出"有光从背后过来"的感觉。文字仍然不用纯白：`#FFF` 压在炭灰上会发青，退到 `#FFFDFA` 才和底子是一家人。

颜色只出现在两处：**在播红**与**封面图本身**。

```css
--ground:     #15161A;                 /* 全局底色：低饱和深炭灰，导航与内容同一层 */
--ground-deep:#0C0D10;                 /* 暗角：四角压深，托住中央的光 */
--glow:       216,166,92;              /* 暖金，写成 RGB 供 rgba() 拼 alpha */
--panel:      #1B1C20;                 /* 卡片图未加载时的底 */
--raised:     #232428;                 /* 极少用：需要"更实一点的底"时 */
--raised-2:   #2C2D32;                 /* 同上，再深一级 */
--glass-tint: rgba(11,12,15,.22);      /* 烟色玻璃底，见 §5.1 */
--wash:       rgba(255,255,255,.055);  /* 静态说明块的薄雾 */
--text:       #FFFDFA;                 /* 主文本（暖白） */
--muted:      #C3C4C9;                 /* 次要文本、未选中标签 */
--faint:      #9C9DA4;                 /* 元信息、时间、人数 */
--live:       #FF453A;                 /* 唯一强调色：在播、进度、主按钮 */
```

**文字灰必须是中性灰，不能带暖调。** 底色从暖褐换成炭灰之后，`#C2B9B1` 这种暖灰会读成脏土色——暖只属于那层光。

### 2.1 中央光晕

```css
background:
  radial-gradient(820px 560px at 50% 41%, rgba(var(--glow),.105), transparent 68%),
  radial-gradient(1720px 1220px at 50% 45%, rgba(var(--glow),.082), rgba(var(--glow),.030) 42%, transparent 70%),
  radial-gradient(1500px 1100px at 50% 46%, transparent 40%, rgba(8,9,12,.74) 100%),
  var(--ground);
```

三层各管一件事：**核部**一小团更亮的金（让光有来源，不是均匀的雾）、**主光**一块 1720px 的椭圆（70% 后完全断掉）、**暗角**把四角压到 `--ground-deep`。

暗角不是装饰，它是让光显亮的手段——**明度对比，不是加亮度**。只加亮度会让整块屏幕发灰，焦点就没地方站了。

**金色要够浓才读得出"金"。** 这是量出来的：底色冷 4 级，金的 alpha 必须满足
`R−B = 128a − 4`，也就是 **a ≥ .08 才有 +6 的暖度**。低于这个值，金光只是在提亮，中心会变成 rgb(41,42,42) 的中性灰——看着像雾，不像光。

**实测**：中心 rgb(49,45,42) L46（暖 +7）／四角 rgb(16,16,20) L16（冷 −4）。

### 2.2 用色规则

- 强调色只出现在：LIVE 圆点、直播进度条、"进入直播间"主按钮。**不用于标题、标签、导航、图表。**
- **不使用四家平台的品牌色。** 平台用两个汉字表示（哔哩 / 斗鱼 / 虎牙 / 抖音），**作光字写在卡片左上角——不加底、不做药丸**（§8.4）。四个品牌色放在一起会让界面失去焦点，在 3 米外也分辨不出来。
- 面之间用明度差分隔，**不用 1px 描边**——1080p 上的 1px 线在沙发上等于不存在，只会变成脏点。
- 不用发光、不用彩色投影。
- **磨砂（`backdrop-filter`）只给有面可控的控件**，且必须配烟色底（§5.1）。纯黑底时代黑底上做模糊什么也看不见，现在底是有光的，模糊才有意义。**Android TV 上 `blur` 会掉帧：整屏几十个模糊层不现实，落地时换成烟色实底（`--glass-tint` 提到 .55），视觉损失比掉帧小。**

**对比度**（对行体 L41 ／ 背景中心 L46）

| 用途 | 色 | 行体上 | 光晕中心 |
| --- | --- | --- | --- |
| 正文 | `#FFFDFA` | 14.0:1 | 13.4:1 |
| 次要 | `#C3C4C9` | 8.2:1 | 7.8:1 |
| 元信息 | `#9C9DA4` | 5.3:1 | 5.1:1 |

均高于 WCAG AA（正文 4.5:1，大字 3:1）。`#8E8F96` 那一档在光晕中心只有 4.2:1，**不达标，已废弃**——亮度抬高之后，弱文字的灰必须跟着提亮一档。

## 三、字体

```
拉丁与数字  Inter（自托管，assets/fonts/InterVariable.woff2）
中文        -apple-system → "PingFang SC" → "Microsoft YaHei" → sans-serif
```

两段式字族：拉丁与数字用 Inter，中文落回系统黑体。这么做的理由有三个——房间号、人数、时长全部是数字，Inter 的等宽数字（tabular）在小数点对齐上比系统字干净；Inter 与 SF Pro 的比例接近，换成 Apple TV 真机时观感不会跳；自托管保证设计稿在任何机器上截出来的图一致。

单一视觉语气，靠字重与字号分层。**最小字重 400，禁用细体**——TV 上的细体在压缩后会消失。

| 令牌 | 字号 | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- |
| `--fs-hero` | 76px | 600 | 1.06 | 首页主图标题（最多 2 行） |
| `--fs-display` | 120px | 600 | 1 | 播放页主播名（换台条大字曾用这一档） |
| `--fs-h1` | 44px | 600 | 1.15 | 界面标题（分类 / 关注 / 搜索 / 设置） |
| `--fs-h2` | 34px | 600 | 1.2 | 内容行标题 |
| `--fs-title` | 26px | 600 | 1.3 | 分组标题（卡片标题已让位给 `--fs-meta`，见 §8.4） |
| `--fs-body` | 24px | 400 | 1.5 | 正文、说明 |
| `--fs-meta` | 22px | 400 | 1.4 | 人数、时长、房间号 |
| `--fs-tab` | 30px | 500 | 1 | 顶部标签 |
| `--fs-card-meta` | 18px | 400 | 1.4 | 卡片副文本（平台 · 主播 · 人数） |
| `--fs-small` | 20px | 400 | 1.5 | 左栏副标题、说明行、设置项描述、弹层正文 |

字距：大字号 `-0.02em`，正文 `0`。数字一律 `font-variant-numeric: tabular-nums`，房间号和人数滚动时不抖动。

**两条硬规则。**

**一、字号下限 22px**（≈tvOS 29pt）。低于这个数在 3 米外读不出来，一律不用。

**二、相邻两档至少差 2px。** 档位多不是问题——Apple 自己的文字 ramp 就有 11 级；问题是"相邻两档只差 1px"，那不是层级，是噪声：用户分辨不出，维护时也无从选择。曾经散着 19/20/21/23/28/36/38 七个脱离令牌的硬编码值，其中 21 与 22 只差 1px、36 与 38 只差 2px 却分工不明。现在全部并入令牌，每屏实际落在 6–8 档、相邻最小间距 2px。

三个例外，都只用在"不承担阅读任务"的位置：

| 例外 | 字号 | 为什么不占 22px 的名额 |
| --- | --- | --- |
| 换台角标、LIVE 标记 | 20px | 贴在封面上的标记，靠位置和字距被看见，不靠读 |
| 卡片副文本 | 18px | 卡片内的第三层信息，看一眼知道是哪家、多少人即可 |

卡片副文本为什么比页面其它 meta 更低一档：卡片标题现在是 22px，配 22px 副文本会糊成一片，读不出主次。退到 18px 拉出 1.22 倍，层级才成立。卡片是信息密度最高的地方，副文本本来就该比别处更弱。

**卡片标题为什么从 26px 降到 22px**：它现在压在画面里。字一旦压在画上，23px 以上就是"字幕"——观众会开始读它，而不是看画面。把字级降下去不是"缩小"，是把主次还给画面（§8.4）。

## 四、栅格与间距

```
画布        1920 × 1080
安全区      四边内缩 60px
内容边距    左右 80px（与安全区叠加后视觉留白 80px）
顶部导航    高 116px，底部与主图间距 32px
内容行间距  56px（行与行之间，明显大于行内 14px）
卡片间距    横向 20px / 纵向 32px（卡片只剩画面，纵向不再需要给文字让路）
```

- **一对等宽外边距**，左右都是 80px，任何界面不破例。
- 行间距（56）必须明显大于块内间距（14/24），否则大屏上会糊成一片。
- 纵向内容超出时整屏纵向滚动，焦点下移自动滚动；下一行的顶部**必须露出至少 24px**，作为"下面还有"的提示（不使用滚动条，3 米外看不见）。

## 五、圆角与控件

| 元素 | 圆角 |
| --- | --- |
| 封面卡 / 面板 | 20px |
| 头像 | 圆形 |
| 按钮 / 标签 / 顶栏胶囊 | 全圆（999px） |
| 列表条目 / 设置行 / 键盘键 | **14px** |
| 输入框 | 20px |

**条目不是胶囊。** 14px 这个数是量出来的：Apple TV 设置页那一行的左缘，y 从 104 到 135 而 x 一直是 48 —— 是一条**竖直线**，不是圆弧。高度 96px 的行套 999px 会变成"药丸"，那是标签的形，不是条目的形。

**按钮只有两种**

1. **主按钮**：白玻璃胶囊，"进入直播间"。全屏最多一个。
2. **次按钮**：半透明玻璃胶囊，白字。

不用第三种。不做描边按钮——描边在大屏上过细。

### 5.1 一块玻璃，一个旋钮

全项目**只有一段**材质公式。每个可聚焦的面自己只声明一个数字 `--a`（体亮度），渐变、边光全部由它算出来。所以 56px 的胶囊、96px 的条目、92px 的键盘键、300px 的弹层，是同一种材质，只是薄厚不同。

```css
.srow,.rrow-s,.sgroup,.rail__item,.chip-t,.key,.btn--ghost,.pbtn,
.p-top__back,.tabs__pill,.hit-go,.seg,.dialog__box,.kb__display{
  background-color:var(--glass-tint);                     /* 烟色底：让面比环境暗 */
  background-image:
    /* ① 暖金顶光：横贯全宽，34px 走完 —— 让面和背景是同一盏灯 */
    linear-gradient(180deg,
      rgba(var(--glow-lit),calc(var(--a,.03) * 1.0))  0px,
      rgba(var(--glow-lit),calc(var(--a,.03) * .30)) 14px,
      rgba(var(--glow-lit),0)                        34px),
    /* ② 中性顶光 + 平体：16px 落到体亮度，之后一路平到底 */
    linear-gradient(180deg,
      rgba(255,255,255,calc(var(--a,.03) * .95))  0px,
      rgba(255,255,255,var(--a,.03))             16px,
      rgba(255,255,255,var(--a,.03))            100%);
  box-shadow:inset 0 0 0 1px rgba(255,255,255,calc(var(--a,.03) * .7 + .045));
  -webkit-backdrop-filter:blur(18px) saturate(150%);
  backdrop-filter:blur(18px) saturate(150%);
}
```

两层在 `0px` 处合计 `1.0a` 暖金 + `0.95a` 白，约等于原来单层白顶光的 `1.9a`——**改的是光的颜色，不是光的多少**。所以档位表一个数都不用动，换掉公式之后原有的明暗关系原样保留，只是暖了。

**`--a` 的档位**（越高越"实"）

| `--a` | 用在哪 |
| --- | --- |
| `.045` | 静态说明块、"跳到"提示 |
| `.055` | 键盘显示框 |
| `.062` | 静置的列表行、设置行、左栏条目 |
| `.10` | 压在画面上的控件、未选中的标签、键盘键 |
| `.165` | ＋关注（一排按钮里的主按钮） |
| `.215` | 焦点行 |
| `.22` | **选中**的标签 / 分组（不是焦点） |
| `.245` | 主按钮的静置态（全站最厚的一片静置面） |
| `.26` | 导航焦点胶囊 |
| `.30` | 压在画面上的焦点（播放控制条、返回按钮） |
| `.34` | 焦点：标签、分组、主按钮、键盘键 |
| `.36` | 焦点叠在已选中的标签上 |

实测量到的面亮度（环境 L26 左右）：未选标签 **L52**、选中标签 **L76**、焦点标签 **L93**；主按钮静置 **L65**、焦点 **L90**；播放控制条静置 **L32**、焦点 **L81**；导航胶囊 **L85**。**它们全部落在 L76–L90 这条带里**，和参考里那颗"账号与同步"（面 L88 / 环境 L33）是同一档。

> 静置行从 `.028` 抬到 `.062`、焦点从 `.175` 抬到 `.215`，都是**背景变亮之后重新量的**，不是审美偏好。原来的档位是在 L8 的黑底上定的：`.028` 的白色叠加刚好让行从 L8 走到 L15（1.9 倍，看得见）。底换成 L27 的炭灰之后，同一个 `.028` 只能把行推到 L32（1.25 倍），面就消失了。**同一块玻璃，背景亮一档，档位表必须重算。**

调一块面只需要改这一个数。**不要再给单个组件写渐变**——写第二段就一定和第一段不统一，这是这一节的全部意义。

#### 烟色底：玻璃要吸收光，不只是叠加光

白色叠加有一个隐含问题：加亮量正比于 `255 − 背景`。**背景越亮，同一条公式加得越少**——环境一旦有心，玻璃就自己消失了。实测：静置行 L32 对背景 L27，只差 5 级，整页面只剩一堆描边。

所以底色不能是"透明"，要掺一层比环境暗的烟色（`--glass-tint`，22% 的近黑）：

| | 只有白色叠加 | 加烟色底之后 |
| --- | --- | --- |
| 面 vs 环境 | L32 / L27（+5，几乎不可见） | L41 / L27（+14，1.5 倍） |
| 在光晕最亮处 | 面被底吞掉 | 面仍然成立（L43 / 46） |

物理上也更对：真实的磨砂玻璃是**吸收 + 散射**，不是发光板。掺暗之后，背后的光是从玻璃里**透出来**的，而不是"玻璃自己变亮了"。

杂色也不能省 `saturate(150%)`：透过白玻璃看金光会发灰，提一点饱和度才保得住暖调。

#### 停靠点用像素，不用百分比

这一条是想清楚才改的。光的衰减距离是一个物理量，**不随物体变高而变长**：

| 用 14% | 面高 | 实际光带 |
| --- | --- | --- |
| 96px 的条目 | 13px | 一段柔边，对 |
| 300px 的弹层 | 42px | 一片灰雾，错 |

同一句公式，在高的面上变成了另一种材质。实测弹层剖面曾是 `L71 → 47`，**拖了 140px**，看起来像一块上亮下暗的灰塑料板。改成绝对像素之后（暖金层 `0 → 34px`、中性层 `0 → 16px`），无论面多高，顶上那道光都是同样一段柔边，然后一路平到底。

#### 顶光是"一段"，不是"一条线"

这是最容易做错、也最容易被一眼看穿的一处。

采样 Apple TV 设置页那一行的纵向亮度：

| y | L | 含义 |
| --- | --- | --- |
| 106 | 157 | 顶沿镜面 |
| 107 | 43 | **下一像素立刻掉光** |
| 131 | 38 | 往下 24px 只掉 12%，**基本是平的** |
| 133 | 118 | 底沿另一道弱亮 |

也就是说：那道 L157 是**一条 1px 的边**，不是一段长尾衰减。把"1px 的边"当成"30px 的面"来实现，就得到一块上亮下暗的灰色塑料块——这是本项目走过的一次真实弯路。

还有一层：**苹果的底本来就亮（L24–41）**，在亮底上加一道亮边是"增添厚度"；我们的底是 L22 的炭灰，同一道线就成了横在方框顶上的一条白杠。所以这里**不做顶沿镜面线**，顶光必须是 `0 → 34px` 衰减完的柔边。

同样地，底边不压暗——压暗会让控件像塑料扣子。

#### 边光由 `--a` 推导

`0.7a + 0.045`。薄的面边光也薄，不会出现"行几乎看不见、边框却很清楚"的怪东西。用 `inset 0 0 0 1px` 而不是 `border`：不占布局、缩放时不会糊成两倍宽。

#### 渐变也能插值

`background-image` 本身不可过渡，直接换 `--a` 会是一记硬切。所以把 `--a` 注册成有类型的数值：

```css
@property --a{syntax:"<number>";inherits:false;initial-value:0.03}
```

注册之后浏览器能对它做插值，渐变里每一层的 alpha 跟着时间走。实测焦点行在 200ms 内 `0.062 → 0.128 → 0.183 → 0.215`——焦点是**亮起来**的，不是跳一下。

#### 白只留给键帽

有一版里，"选中"是靠**翻成白底黑字**表达的：主按钮、当前标签、播放控制条、返回按钮，一获得焦点就变成一张白纸。这条路走不通——旁边每一块都是暖灰玻璃，只有它是一张纸，屏幕上于是有两种材质在互相否认。

现在**选中一律是同一条灰阶上厚一档**（见上面的档位表），白退到只剩一个地方：

| token | 值 | 用在哪 |
| --- | --- | --- |
| `--grad-paper` | `#FFFCF4 → #F9F4EB 46% → #EFE8DD` | **只有键盘键帽**（且是焦点态） |
| `--grad-paper-on` | `#FFFEFA → #FDF8F0 46% → #F2ECE2` | 同上，再白一档 |
| `--rim-paper` | `inset 0 0 0 1px rgba(255,255,255,.55)` + 极小外落影 | 让键帽从暗底上分出来 |

为什么键帽可以例外：**它有现实原型。** 键盘上的字键本来就是浅色的，焦点键发亮就是"这颗键被按下去"；而"进入直播间"没有原型，它变白只说明它和邻居不是同一种东西。**例外需要物理依据，不能只是"想让它更醒目"。**

实测键帽焦点：顶部 **246**、底部 **229**，差 17 级——看得见厚度，又不会脏。白也是暖的（三个停靠点 B 通道各让 3–5 格），因为它和背景那盏暖金是同一盏灯；**不是给白加黄**，起点仍是 253。

#### 两个例外，各有理由

- **弹层**（`.dialog__box`）是这一族里最实的一块：`rgba(25,24,24,.9)` + 磨砂，只留一成透光。它要托住一段正文，全透上来就糊了；全实心又会变成屏幕正中一块灰塑料。
- **落影只给焦点，不给面**。理由和上一轮相反，因为底变了：真黑底上投影落进黑色等于没有，加它只是让代码"看起来像 Apple"；现在底是 L27 的炭灰、中央还有光，落影是真能看见的。所以焦点态多一条 `0 22px 48px -22px rgba(0,0,0,.72)`——**这是"悬浮质感"最省力的一笔，也是唯一该花的地方**。整屏四十个行各铺一层落影，GPU 全花在看不见的地方。

## 六、焦点（最重要的一节）

在电视上，焦点就是光标。焦点错了，整个产品就废了。

### 6.1 焦点样式

**不放边框。** tvOS 的焦点不画环，靠"这块内容被举起来了"来表达：变大、变亮、底色抬一档。加环会把界面切成一格一格的表格，也违背"内容优先"。

| 属性 | 未聚焦 | 聚焦 |
| --- | --- | --- |
| 缩放 | 1.00 | **1.08**（封面卡）/ **1.06**（按钮、按键）/ **1.02**（列表项） |
| 边框 / 外环 | 无 | **仍然无**（不许出现描边） |
| 封面亮度 | 0.95 | **1.04** |
| 卡片标题 | 白色 | **仍是白色**（压在画面上，不随焦点变色） |
| 表面 | 玻璃，`--a:.062` | 同一块玻璃提亮到 `--a:.215`（压在画面上、标签、主按钮时见 §5.1 档位表） |
| 落影 | 无 | 一条柔落影（底不再是纯黑，投影看得见了） |

> 投影为什么回来了：上一版底是 L8 的黑，投影落进黑色里等于没有，所以刻意不用。现在底是 L27 的炭灰、中央还有一团光，投影是真能看见的——于是它只给焦点加一条（`0 22px 48px -22px`），静置的面一条都不加。**"浮起"仍然主要交给 scale 和亮度差**，投影只是补最后那一层，四十个行各铺一层就是把 GPU 花在看不见的地方。三米外靠尺寸差和亮度差就能认出来，这是电视上最稳的焦点信号。
>
> 为什么不用白环：白环是键盘焦点（focus-visible）的语言，不是电视的语言。它会让每个卡片看起来像一个格子，压过封面本身。

**"焦点落在白面上"这件事不存在了。** 上一版专门为它写了一条"反色填充"规则：白按钮获得焦点时再白一档、文字转黑、整块放大。现在全站没有白面（见 §5.1「白只留给键帽」），这条规则随之作废——**焦点只剩一件事：把同一块玻璃推亮、放大、浮起来。** 少一条分支，就少一处不一致。

> 注意：厚度来自"一圈 1px 边光 + 一段 34px 暖金顶光"，不是来自外投影。落影只回答"它离开背景多远"，不回答"它有多厚"。

### 6.1.1 顶栏胶囊跟着焦点滑

顶栏的五个页签**不是各画一块底**——那会让屏幕同时亮起五个"选中项"，正是 tvOS 最忌讳的事。正确做法是**一层玻璃胶囊跟着焦点移动**：

- 胶囊是 `.tabs` 内的绝对定位元素，位置由 `offsetLeft / offsetWidth` 算出（不用 `getBoundingClientRect`，后者读到的是过渡中的中间值，胶囊会追着跑偏）。
- 焦点进入顶栏 → 胶囊淡入并滑到该页签下；焦点离开 → 淡出。
- 换屏时传 `instant`，新屏的胶囊直接出现在正确位置，不从上一屏滑过来。

顺带解决了原本最弱的一处焦点目标：页签从 `padding:10px 2px`（约 50px 高）变成 `11px 24px` + 胶囊，可点区域和视觉重量都到了按钮的量级。

### 6.2 焦点规则

1. **每屏必须有默认焦点**，且是用户最可能想要的那个（首页 = 主图主按钮，分类 = 第一张卡，设置 = 第一组）。
2. **离开再回来，焦点回到原处**，不重置。
3. **焦点不可困住**：任何位置按任意方向键都要有去处，没有去处就交给上一级。
4. **焦点移动必须空间可预测**：右就是右，绝不跳过中间元素。
5. 焦点移动只做 `transform` / `--a` / `color` / `box-shadow`，时长 **200ms**，缓动 `cubic-bezier(.32,.72,0,1)`。这几个属性必须写在同一条 `transition` 里——漏掉 `box-shadow` 就会出现"块变大了、高光没跟上"的两半不同步；漏掉 `--a` 则会出现"块在动、亮度已经跳完了"。
6. **放大要有余量**：卡片放大 1.08 会向外顶出约 8% 尺寸。卡片只剩画面之后，纵向只长 15px，行间距 32px 就够；横向 20px 的缝比"各长 13px"窄 6px——**聚焦的卡会压住邻卡左右各 3px，这是有意的**，被举起的那一张本来就该盖在前面（tvOS 同理）。分组标题下沿距网格仍需 ≥ 34px，否则聚焦的卡会啃到标题。

### 6.3 遥控器键位

| 键 | 全局 | 播放页（控制条隐藏） | 播放页（控制条显示） | 换台条打开 |
| --- | --- | --- | --- | --- |
| ↑ / ↓ | 上下移动焦点 | **换台**（上/下一台） | 切换按钮行 | 上/下一台 |
| ← / → | 左右移动焦点 | **换平台**（该平台第一条） | 切换按钮 | 换平台 |
| OK | 确认 | 显示控制条 | 执行 | 确认并关闭 |
| 返回 | 上一级（最高级回首页，不退出） | 回首页 | 隐藏控制条 | 关闭换台条 |
| 数字 0–9 | 无（首页 / 播放页不响应数字键） | 输入数字，与字母同键 | — | — |
| 菜单 | 打开设置 | 更多（清晰度/线路） | — | — |

**返回键规则**：最高级页面按返回，先回首页；首页再按返回，弹二次确认"退出 LiveHub？"。**永远不直接退出 App**——这是电视端最常见的挫败。

### 6.4 四向键的落点怎么算

这条得写进交接文档，否则开发会自己发明一套，然后"按右跳到奇怪的地方"这类问题会反复回来。

**不能按中心点距离排序。** 设置页从左侧导航按右，顶栏「首页」的水平中心只差 37px，而右侧第一行设置差 904px——它就近了，焦点窜到顶栏去。窄而长的元素在中心点距离上永远占便宜。

正确的算法分两步：

| 步骤 | 判据 | 作用 |
| --- | --- | --- |
| 筛方向 | 候选的**中心**必须在按键那一侧（> 4px） | 防止走到背后去 |
| 排序 | 按**边缘间隙**，哪一个真分开了就按分开多远排；副轴间隙 ×3 | 防止跨区抢焦点 |

**方向判据不能也用间隙**：首页第一次按右，301 那张卡的左边缘比"进入直播间"按钮的左边缘还靠左，间隙是负的，可它明明是这一行最该去的地方。中心差能过，间隙不能。两条判据各管一件事。

**副轴权重 3 是量出来的**，不是拍的：设置页那组候选里，顶栏 tab 的副轴间隙 225px、右侧设置行 0，权重低于 3.2 时 tab 会赢。

验收标准：全量跑一遍，五个屏 125 个可聚焦元素 × 4 方向 = 500 次，"不在边界却按不动"必须为 0。当前 0。

## 七、动效

**所有时间参数的来源**：tvOS 内置的 focus hover 是 **~200ms 的透视抬升 + 一道镜面光泽**。这是平台给的基准，不要自创更快的手感——比系统快会让界面显得神经质，比系统慢会让遥控器发黏。

| 场景 | 参数 |
| --- | --- |
| 焦点移动 | **200ms**，`cubic-bezier(.32,.72,0,1)` |
| 按压回弹 | **120ms**，`scale(.96)`（必须比焦点快，否则按下去像没反应） |
| 顶栏胶囊滑动 | 260ms（它要走一段距离，需要比单点缩放久一点才不跳） |
| 界面切换 | 交叉淡入 240ms + 缩放 0.985 → 1 |
| 换台条弹出 | 从底部 60px 上浮 + 淡入，280ms |
| 封面加载 | 淡入 200ms，`--panel` 打底，禁止骨架屏闪光 |
| 弹幕 | 24s 横穿，右上到左，线性 |
| **开关位移** | **180ms**，`cubic-bezier(.4,0,.2,1)` |
| **开关变色** | **120ms**，延后 **55ms**，`--ease` |

一条过渡覆盖四个属性：

```css
--t-surface:transform var(--dur) var(--ease),
            --a var(--dur) var(--ease),
            background-color var(--dur) var(--ease),
            color var(--dur) var(--ease),
            box-shadow var(--dur) var(--ease);
```

- 只动 `transform` / `background-color` / `color` / `box-shadow`，不动 `width` / `top` / `left`（会触发布局）。
- **按压态必须与焦点态用同一条过渡**，只把时长压短。分开写会出现"先跳再动"。
- `prefers-reduced-motion` 降级：把 `--dur` / `--dur-press` / `--dur-sw` / `--dur-sw-color` 压到 1ms、`--sw-delay` 归零，**不删 transform**——本项目没有边框，缩放是唯一的焦点线索，状态必须到达、过程才去掉。
- **任何内容都不许依赖动画才出现**——脚本失败时内容必须已经在那里。

### 7.1 为什么"按钮切换"必须有动画

遥控器没有触感反馈，也没有鼠标悬停。用户按一下，唯一的确认就是**眼前那块东西变了**。如果状态是瞬跳的，大脑读到的是"闪了一下"，而不是"我移动了焦点"。动画在这里不是装饰，是**因果关系的表达**：先有按键，后有变化，中间那 200ms 就是"听到了"。

反过来，动画也不能长到让人等待。200ms 是 Apple 在电视上验证过的数字：短到感觉即时，长到能被看见。

### 7.2 开关不能借焦点曲线

**焦点和开关是两种运动。** 焦点是"一块面被举起来"，面可以极快起步，没有位移；开关是"一个点滑过去"，点的起步必须能被看见。把焦点那条 `.32,.72,0,1` 直接套到滑块上，结果是"冲一下然后卡住"。

这不是感觉，是采样出来的。每 20ms 读一次 `::after` 的 `DOMMatrixReadOnly(...).m41`：

| 时刻 | 位移 | 占比 |
| --- | --- | --- |
| 22ms | 9.2px | 24% |
| **86ms** | **31.7px** | **83%** |
| 235ms | 38.0px | 100% |

前 86ms 冲掉五分之四，剩下的 150ms 只挪 6px。曲线没问题，是**用错了地方**：它的起点加速度是为"面被托起"设计的，给一个 38px 的位移用，就变成一记弹射。

过冲曲线 `.34,1.4,.64,1` 更糟：64ms 就走完 80%，滑块早早到站，轨道怎么调都追不上，看上去是滑块先飞过去、轨道在后面慢慢亮。

最终定案：

```css
--dur-sw:180ms;                      /* 位移 */
--dur-sw-color:120ms;                /* 滑块变色 */
--sw-delay:55ms;                     /* 等位移走过大半再翻色 */
--sw-ease:cubic-bezier(.4,0,.2,1);   /* Material standard，位移与轨道共用 */
```

改完的采样，每 20ms 推进 **0.8 / 10.9 / 9.2 / 6.6 / 7.1 / 1.7 / 1.1 / 0.5**——一段连续滑行，末端 3.4px 摊在 72ms 里，读作"靠住"不是"拖住"。

三条约束：

- **变速和动位移不能同起同止。** 两者同时跑，中途那一帧是"灰滑块 + 半亮轨道"，对比度最低，眼睛只接住一次闪。延后 55ms：先看见它滑过去，再看见颜色反过来。
- **颜色曲线不能过冲。** 位移可以，alpha 不行——顶到 1 就提前饱和，后面的时间等于白等。
- **轨道必须和滑块同一条曲线。** 它们是一个东西在动；轨道自己用更快的曲线就会抢在滑块前面亮一下。

> 采样方法：CDP 每 20ms 读 `getComputedStyle(el,'::after')`，`DOMMatrixReadOnly` 的 `m41` 给位移，`backgroundColor` 给颜色。主观的"不流畅"必须先翻译成数字，否则每一轮修改都只是换一条没验证过的曲线。

```
├─ 视频 + 弹幕
├─ 顶部信息条（平台 / 主播 / 房间号 / 标题 / 人气 / 画质）
└─ 底部控制条（弹幕 / 清晰度 / 线路 / 换台 / ＋ 关注）

换台条（播放页 ↑↓ 呼出）
└─ 大号主播名 + 预览图 + 标题 + 平台·房间号 + 人数

设置
├─ 播放（解码 / 画质 / 线路策略 / 缓冲）
├─ 弹幕（字号 / 速度 / 密度 / 屏蔽）
├─ 账号与同步（扫码 / 同步码）
└─ 关于（版本 / 内容来源 / 开源许可）
```

**首页为什么去掉"关注的主播"和"平台索引"**：首页只回答"现在有什么好看"。把关注塞进首页，会让推荐流被个人订阅切碎；把平台入口塞进首页，会把"换台"这件动作变成"先看表再按键"。两件事各自有归宿——关注去关注页，平台去分类页。首页保持纯粹的推荐流，是这一版最重要的取舍。

**卡片网格为什么是 3–4 列而不是 5 列以上**：三米观看距离下，卡片宽度低于 400px 时封面里的人脸就糊了，标题也只能塞下 8 个字。一行 4 列是"能认出是谁"的下限；再密就退化成缩略图墙。搜索页因为右栏被键盘让走了 830px，只能用 2–3 列。

**首页的热门推荐为什么不再横滑**：横滑一次只能看见四张，而且"还有更多"这个信息藏在屏幕外，遥控器上下键的直觉是"往下还有"。改成和关注页同一套竖排网格，一屏看见八张，往下滚就是翻页。横滑只适合"每项都很宽"的封面流，这里的卡片本来就不宽。

**每个界面只回答一个问题**：首页"现在有什么好看"、关注"谁在播"、分类"某平台某分类有什么"、搜索"那个主播在哪"、播放"看得爽不爽"、设置"怎么调成我要的样子"。

### 8.1 设置页：左边只读，右边才是操作

设置页左右两栏**不共用焦点语言，因为左栏根本不参与焦点**。

早期版本让左栏也承担导航（竖排分组，可聚焦，焦点态是一枚玻璃胶囊）。问题在于：屏幕上同时出现两个可操作区，遥控器按一下右键就得先猜"我要去改分类还是改设置"。而且竖排 340px 的左栏把右栏挤得只剩一条。

现在左栏只回答一个问题——**"我现在是什么状态"**：

| | 左栏（状态卡） | 右侧（条目 + 分组条） |
| --- | --- | --- |
| 可聚焦 | **否**，一个可聚焦元素都没有 | 是 |
| 底色 | `--wash`（`rgba(255,255,255,.055)`），平的，不随焦点变 | 玻璃，`--a:.062` → 焦点 `.215` |
| 圆角 | 28px | **14px** |
| 内容 | 当前分组的大标题、一句解释、几条 key-value、一行注 | 改设置的条目 |
| 职责 | 解释状态，不提供动作 | 提供动作 |

分组条改成**横排**，放在右栏顶上，四个分组平铺一行。它们仍是可聚焦元素（`--a:.10` → 选中 `.22` → 焦点 `.34`，scale 1.04），但语义上属于右栏——它们是"这一栏显示哪一组"，不是"另一个操作区"。分组条和分类页的标签是同一个控件、同一组档位，两处不能各定一套。

**默认焦点落在第一个条目上**，不是分组条，也不是左栏。理由：进设置页是想改设置，不是改分类。

行内控件同样必须是玻璃，不能一半玻璃一半纯色：

- **分段控件**：轨道是 `rgba(255,255,255,.08)`（`--a:.06`）；选中项由一枚**滑动的玻璃药丸**（`--a:.34`，260ms）表示，而不是给某个 `<b>` 加底色——加底色就是硬切，眼睛接不住切换。药丸以前是白的：白底黑字在一条灰玻璃行里，是整页唯一一块反相的东西。现在它和分类标签的"选中"是同一档。
- **开关**：关态轨道是玻璃，开态转白；滑块 180ms 滑过去，变色延后 55ms（见 7.2）。

**`<button>` 必须显式 `background-color:transparent`**。这条踩过坑：浏览器自带一层 UA 底色，会从半透明渐变底下透上来；焦点态越透，露得越多，整块胶囊糊成一块白。分组胶囊就因此白过一次。

**条目不是卡片**。右侧不再是"一张卡片里装若干行"，条目直接铺在炭灰底上，靠自己的面分界，零描边。内容多时只有条目区滚。

> 药丸定位的两个坑：一是用 `offsetLeft / offsetWidth`，`getBoundingClientRect` 会在面板重渲染那一帧读到布局前的值；二是 `getComputedStyle` 返回的是**实时对象**，想比较前后两个状态必须立刻把值抄成字符串，否则两次读的是同一个对象。

### 8.2 滚动：谁滚、谁不动

五个屏分两类，没有第三种：

| 类型 | 屏 | 行为 |
| --- | --- | --- |
| 单栏 | 首页、关注 | 整页一个滚动容器 |
| 分栏 | 分类、设置、搜索 | 左栏钉死，**只有右栏滚** |

判断依据不是屏幕尺寸，是**左栏承担什么职责**。分栏页的左栏是"我在哪"的坐标系（分类页＝平台与在播数量／设置页＝当前分组的状态卡／搜索页＝输入键盘），跟着内容滚走，用户滚到第二屏就不知道自己站在哪了。单栏页没有这个坐标，标题跟着走没有损失。

设置页的分组条虽然回到了右栏顶部，但左栏仍然是那个坐标系——它被换成了一张**只读状态卡**，说的还是"你现在在哪一组、现在是什么设置"。

实现只有一行是命门：

```css
.browse{flex:1 1 auto; min-height:0; display:flex}
```

**`min-height:0` 不能省。** flex 子项默认 `min-height:auto`，意思是"我不能比内容更矮"。于是内部那个 `overflow-y:auto` 的容器会被内容顶开，高度永远等于内容高度，滚动条永远不出现，整页跟着一起滚——这是"我明明写了 `overflow:auto` 却不滚"的唯一原因。

设置页的面板多两行：

```css
.panel{align-self:flex-start; max-height:100%; overflow-y:auto}
```

两个缺一个都不对：

- 只留 `align-self:flex-start`：内容少时是一张内容高的卡片（对），内容超长时溢出到屏幕外（错）。
- 只留 `max-height:100%`：每张面板都被撑满整列，内容少的组下半截空着，像一块没做完的白板。

还有一条容易忘的连带责任：**面板变成自己滚之后，换分组必须手动 `scrollTop = 0`**。上一层滚到一半切过来，新分组会从一个莫名其妙的位置开始。

**"能滚"要有量，不能只有声明。** 设置页原先是 15 项，加起来正好 773px，等于可视高度——`overflow:auto` 写了，但一条都不需要滚，这个特性等于不存在。扩到 23 项后才真的可滚 103px。凡是"支持滚动"的需求，都要量 `scrollHeight > clientHeight`。

焦点移到视口外会自动带动最近的滚动祖先，不用写代码：`setFocus` 到最后一张分类卡，右栏自己滚到 940px，卡片落在 y=809–1080 完整可见。

**滚动容器要把裁剪边界退出去 14px。** `overflow:hidden` 是在**容器的 padding 边**上切的，而焦点行还会放大 1.02——1200px 宽的行左右各长 9px，正好被这条线切掉，左端圆角被切平，看起来像"被左边的什么东西压住了"。

```css
.results{margin-left:-14px; padding:0 var(--gut) 80px 14px}   /* 边界退到 940，行最远到 945 */
.spane{margin:0 -14px; padding:6px 14px 26px}                 /* 设置页同一个手法 */
```

负 margin 配等量 padding，内容位置一格不动，只是把裁剪线挪到外面。**这 14px 要加在滚动容器自己身上**——加在行上没用，裁剪边界不跟着行走。

**分类页的卡片要退 16px，不是 14px。** 同一个病，参数不同：卡片放大 1.08，334px 的卡左右各长 13.4px，比行（1.02 / 各 9px）长得更多。左栏右缘在 400，卡左缘 444，看着还有 44px 余量，可 `.grid-area` 自己的裁剪线在 428——**不是左栏压过来，是容器在切自己的内容**。

```css
.grid-area{margin-left:-16px; padding:0 var(--gut) 60px 16px}  /* 裁剪线退到 428，卡最远到 430.6 */
```

凡是"滚动容器里放着会放大的元素"，边界都要按**最大放大后的外扩量**退，而不是按元素本身的 padding。

**播放页的顺序为什么是 `弹幕 → 清晰度 → 线路 → 换台 → ＋ 关注`**：前四个都是"看这一次"的参数，关注是"以后都看"的动作。它不在这条参数链上，它是出口，所以放末尾。它和四个玻璃胶囊的区别只有一档厚度（`.10` → `.165`，字重 600）——**播放页压在画面上，任何变白的控件都会和画面抢亮度**，所以这里连"主按钮更白"都不给，只给"更厚"。

### 8.3 搜索：一块键盘，一种输入

**上一版做错了什么**：键盘分「字母 / 数字」两个模式，中间放一枚 `123` 切换键，输入框左上角再挂一枚「数字」徽标。要搜「小鹿233」，得按 `123`、打三位数字、再按 `ABC` 切回来。

这个设计的病根不在交互，在**前提**：它假定"数字"是另一种搜索任务（查台号），所以要一个独立模式。而台号不存在（见第一章），"我现在要输入数字"这件事本身就不该发生。

**现在的做法**：只有一块键盘。

```
┌──────────────────────────────────────────────┐
│ 输入框（96px，等宽数字，占位提示里写清能搜什么）        │
├──────────────────────────────────────────────┤
│ 1 2 3 4 5 6 7 8 9 0        ← 数字行，十列满铺，与字母同尺寸 │
│ Q W E R T Y U I O P
│  A S D F G H J K L         ← 短行错位：缩半键
│   Z X C V B N M            ← 短行错位：缩一键半
│ [ 删除 ] [ 清空 ] [  搜索  ]  ← 跨度 3+3+4 凑满十列
└──────────────────────────────────────────────┘
```

- **数字行在最上面、和字母同宽同高。** 不是"另一个模式"，是同一块键盘的一行，像实体键盘那样。上一版数字键是 155×145 的大键，因为那时数字只用来打台号；现在数字是自由输入的一部分（房间号 4–10 位、抖音号里也有数字），和字母同等地位，也就不该有不同的尺寸。
- **键高一律 92px，加一行不改任何一枚键的手感。** 五排：5×92 + 4×14 = 516。键盘拿到的高度预算是 621（809 − 32 上边距 − 96 输入框 − 28 间距），516 之后余 105，键盘不下沉、底边留白。
- **工具行从 2+2+2+4 变 3+3+4。** 空出来的那一列是原来的模式键位置，平均分给两个工具键；搜索键仍是最宽的 4 列——它是这一屏唯一的下一步。
- **不做"字母/数字"混输的语法限制。** 只挡输入框容量（12 位），不挡内容。任何"第几位之后不许输入"的规则都会误伤房间号或抖音号。

**匹配规则（`searchHits`）**

只按"匹配得有多准"分三档，**没有字段权重**：

| 档 | 条件 | 说明 |
| --- | --- | --- |
| 0 完全相等 | 主播名 / 房间号 / 抖音号 / 拼音 / 标题 | 唯一指向一个直播间，结果区给一句「按「搜索」直达」 |
| 1 前缀 | 房间号 / 拼音 / 主播名 | 从头开始打是这类输入的习惯，比"包含"更可信 |
| 2 包含 | 主播名 / 标题 / 房间号 / 分类 | 分类命中的是一类、不是一个直播间，所以固定落最后一档——"游戏"不该排在任何具体直播间前面 |

上一版有「台号 > 主播名 > 标题 > 分类」这条业务权重。台号不存在，权重也就不该存在：权重是在补偿一个虚构字段的精度优势。

- `rid` 一律当字符串比，**永远不 `Number()`**。哔哩 8–10 位、斗鱼 4–8 位、抖音号是"字母+数字"，转成数字会把台账打乱。
- 直达提示的判据是"排第一的那条 `rank === 0`"，**不是"输入了几位数字"**。任何按位数写死的条件都会把 `9999`（斗鱼短号）和 `xiaojiuguan`（抖音号）挡在门外。
- 「搜索键打开第一条」和「直达提示」共用同一个 `hits[0]`，两者不可能不一致。
- 空查询不显示结果，最近搜索顶上来当主角。上一版固定摆四张卡，等于说"什么都没输也有结果"。
- 最近搜索存的是**你打过的那串字**（`660000` / `lpe` / `xiaojiuguan`），点一下填回输入框；不是四条直播间。

**最近搜索是网格，不是列表。** 一行一条会在 886px 宽的右栏里拉成一根 880px 长的横条，读起来是"列表里的一项"，而这四五个短词的地位是平行的：

```css
.recent{display:grid; grid-template-columns:repeat(auto-fill,minmax(320px,1fr)); gap:12px}
```

- 栏宽 886 时正好两列（每块 437），四个词排成 2×2；栏窄一档自己掉成一列，宽屏也不窜到三列——三列每块只剩 287px，`xiaojiuguan` 这种 11 个字符的抖音号就被截了。**不写死列数，让 `minmax` 去决定**，因为能放几列只取决于栏有多宽。
- 每块都是自己一整圈 14px 圆角，所以必须有缝。零间距时两条圆弧在接缝处一夹，夹出一条上宽下窄的锯齿黑线——既不像分组（分组只在两端圆角），也不像独立的两块。12px 与 `.sgroups` 同值。
- 方向键不用改：寻焦是几何的（`moveFocus` 按中心差和边缘间隙打分），网格里左右换列、上下换行自然就对。
- 时间文字是这一块里最弱的字，但"次要"不等于"看不见"：`--faint`（4.9:1）而不是写死的 `#5A5A5E`（1.3:1，三米外等于没有）；焦点块提亮到 L108 之后抬到 `--muted`。

**已知取舍**：屏上键盘只能产出 ASCII，所以中文主播名、中文标题、中文分类这三条匹配分支从键盘这条路走不到——它们留给系统输入法与语音搜索。占位提示因此写的是"拼音首字母、房间号或抖音号"，不承诺"输入中文也能搜"。匹配函数保留中文分支，是因为产品接上语音/输入法之后它就是对的；但界面文案不能替它吹牛。

**v1 约束（抖音）**：上面那套匹配对三家有效，**抖音在 v1 只返回 0 条**——它不参与关键词搜索（`capabilities.search = false`），输入抖音号也查不到（反查要签名，见 `04-Android架构.md` §4.1）。所以结果区为空时要按平台给不同的话：其它三家空 → 「未找到」，抖音相关的空 → 「抖音请粘贴直播页链接或房间号」。这不是补丁式特例，是因为抖音在这一屏**确实处在另一个能力状态**：它只接受粘贴，不接受检索。等 v2 签名接上，这段文案和 `capabilities.search` 一起删。

### 8.4 卡片是画面，不是信息块

上一版一张卡是两截：上面 16:9 封面，下面一块 `padding:16px` 的正文区（标题 26px + 副文本 18px）。信息上很规整，但它把"看什么"和"这是什么"分成了上下两件事——眼睛先看图，再往下挪一行读字。卡片于是变成"一张带图的信息块"，而不是"一个节目"。

苹果在电视上从来不把封面当插图。tvOS 的规矩是**内容即界面**：屏幕上最亮、最大、最完整的那块必须是内容本身，其余一切——标题、平台、状态、控制条——都只是浮在它上面的标注。于是：

| | 上一版 | 现在 |
| --- | --- | --- |
| 卡片结构 | 封面 + 独立正文区 | **只有封面**，正文绝对定位压在画面下沿 |
| 卡片标题 | 26px / `--muted`，焦点转 `--text` | **22px / 白**，不随焦点变色 |
| 副文本 | 18px / `--faint` | 18px / 白 78%，一层 1px 影 |
| 平台名 | 药丸（玻璃底 + 10px 圆角 + 12px 内距） | **光字**，两层影 |
| LIVE | 红底胶囊 + 白点 | **光字**，字距 `.14em` |
| 封面亮度 | .86（为了给正文区让路） | .95，焦点 1.04 |

**一、标签一有底，屏幕上就多一张纸。** 胶囊、玻璃、半透明烟色，试过三轮——只要它有一层底，它就是"贴在封面上的小纸片"，和"内容即界面"直接矛盾。平台名和 LIVE 属于元信息，元信息就该退到字里去。没有底之后，字靠两层影站住：一层 1px 几乎纯黑的贴边影收锐度，一层 14px 半透的散影托住；压在 LED 墙那种白亮画面上也不飘。

**二、正文压上画面，就必须给它一块暗。** `.card__media::after` 是一条 50% 起笔、100% 收到 `.72` 的渐变——这是字幕底，不是装饰。50% 是量出来的：起早了（44% 试过）整张封面被一道斜灰切成上下两半，看着像叠了两张图；收口收到 `.90` 也试过，卡片立刻退回"一块黑底板上放两行字"，画面又没了。**剩下的对比度交给字自己的影，不要用黑去换。**

**三、字级要降，不是升。** 压在画面上的字一上 23px 就变成字幕，观众开始读它而不是看画面。标题从 26 降到 22（`--fs-meta`），副文本保持 18，两者拉出 1.22 倍层级——**卡片里最响的东西必须是画面，字只是名字。**

**连带变化**：卡片变矮了（380×214，不再是 380×294），网格纵向间距 36 → 32。横向 20px 的缝比放大后各长 13px 窄，聚焦的卡会压住邻卡左右各 3px——这是对的，被举起的那一张本来就该盖在前面。

**没做的事**：没加描边、没给封面加内阴影、没在焦点态做"白投影"。三条都会让卡片重新变回"格子"。

**一处排版细节**：`LIVE` 的 `.14em` 字距是加在每个字**后面**的，最后一个字后面那 `.14em` 是白留的——不补 `margin-right:-.14em`，右对齐就差 2.8px，一眼看得出没贴线。

## 九、播放页：画面永远是屏幕里最亮的东西

这一节是照 tvOS 26 的原话定的：「始終以內容為觀看體驗的核心」——快轉、睡眠計時器、調音量、控制中心這些场景，都保持影片置前、置中。

### 9.1 不调曝光，只压两条带

早先的做法是给视频挂 `filter:brightness(.78)`，控制条收起时挂 `.92`。等于用户看两小时直播，两小时都在看一张被调低曝光的画面。

量过才知道亏：对四张真实封面做条带亮度采样、再乘遮罩 alpha 算对比度，**这层压暗对顶栏文字的对比度只贡献 +0.4～+1.0（19.4 → 19.0 这种量级），代价是整幅画面亮度直接乘 0.78。**

现在：

```css
.player__video{ /* 不挂 filter */ }
.player__scrim{
  background:linear-gradient(180deg,
    rgba(0,0,0,.90) 0%, rgba(0,0,0,.74) 12%, rgba(0,0,0,.44) 20%, rgba(0,0,0,0) 36%,
    rgba(0,0,0,0) 55%, rgba(0,0,0,.58) 74%, rgba(0,0,0,.82) 88%, rgba(0,0,0,.94) 100%);
}
```

顶栏（y 5%–14%）与底栏（y 83%–95%）所覆盖的两条带子被压到 0.6–0.9，**36%–55% 的画面中段一点不碰**。

### 9.2 收起控制层，把整块屏幕还回去

`playerState === 'idle'` 时，遮罩一起 `opacity:0` 淡出，而不是"只把按钮藏起来、画面还蒙着一层"。

### 9.3 浮层文字要自己保证可读，不能要求画面让路

换台提示原用 `--faint`(#8E8E93)，落在最亮的那张封面（LED 墙）上实测只有 **2.55:1**。改成 `--muted`(#B4B4B4) 并把底栏那段遮罩加深后，最差一张 **4.74:1**。

这和弹幕用描边代替投影是同一条原则：**可读性是文字的責任。** 反过来做——为了让一行说明看得清而把整部片子压暗——是本末倒置。

### 9.4 控制层占多少画面

| 状态 | 顶栏 | 底栏 | 换台卡 | 占屏比 |
| --- | --- | --- | --- | --- |
| 控制条显示 | 96px | 124px | — | 20.4% |
| 换台条 | 96px | 124px | 237px | 48.2% |
| 收起 | — | — | — | 0% |

视频始终 1920×1080 满屏，**不因控制层出现而被推挤、缩放或改变构图**。

## 十、状态设计

| 状态 | 呈现 |
| --- | --- |
| 在播 | 红点 + "直播中" |
| 未开播 | 灰点 + "未开播 · 预计 20:00"，封面对比度降到 0.5 |
| 线路异常 | 卡右上角"线路异常"胶囊，点击直接进备用线路 |
| 已降级 | 播放页角落一行小字："已自动切到备用线路 · 720P" |
| **清晰度受限（未登录）** | 清晰度胶囊显示**服务端真实返回的档位**（哔哩未登录是「超清 1080P」，**不写「原画」**）；用户切到更高档但服务端降档时，胶囊回落 + 角落一行"未登录，最高 1080P"。设置里的「画质偏好」**只列真实存在的档位**，不放选了没反应的选项。理由：用户能接受"没登录所以只有 1080P"，不能接受"选了原画结果还是 1080P" |
| 加载中 | `--panel` 纯色 + 平台名，不闪光、不骨架跳动 |
| 空（无关注） | 一句说明 + 一个动作："还没有关注的主播。在播放页按 OK 就能关注。" |
| 无网络 | 整屏说明 + "重试"按钮，不显示任何假卡片 |

**原则：宁可少一个卡片，也不显示一个点进去会黑的卡片。**

## 十二、开发交接要点

1. 所有尺寸按 1920×1080 稿 1:1 标注，dp 换算 = px（Android TV density 通常 1.0 或 2.0，按 1080p 基准实现）。
2. 焦点用 Android 原生 `requestFocus` / `nextFocusDown` 等属性，**不要自定义焦点引擎**——系统焦点已经处理了空间寻址，自定义只会更难调。
3. 卡片统一 `CardView` + `focusable`，在 `OnFocusChangeListener` 里做**缩放 + 体亮度**，用 `ViewPropertyAnimator`。**不做焦点环**（见 §6.1）。
4. 图片加载用 Glide/Coil，占位色 `#1B1C20`，禁止占位图。
5. 关注的直播间按 `rid` 持久化，跟账号走，跨端同步；`rid` 是各平台自己的号，不做转换。
6. **材质公式落成一个 drawable**：`linear-gradient` 三个停靠点 + 一圈 1px 内描边，参数只有一个体亮度。Android 里做成 `<shape>` + `GradientDrawable`（`setColors` / `setCornerRadius` / `setStroke(1, color)`），或者一个传 alpha 的自定义 `Drawable`。**每个控件各写一套背景，就是这套设计散架的开始。**
7. **背景不是一个颜色，是一层"光 + 暗角"**。落地时做成一个铺满根布局的 `Drawable`（两个 `RadialGradient` + 一个反向 `RadialGradient`），或者一张 1920×1080 的 9-patch/位图。**不要给每个页面各写一份渐变**，滚动时背景必须纹丝不动。
8. **`backdrop-filter` 别照搬**。原型里每个玻璃面都有 `blur(18px) saturate(150%)`，整屏四十多个模糊层在电视芯片上不可能跑满 60fps。Android 端把 `--glass-tint` 从 `.22` 提到 `.55` 换掉模糊，只在播放页控制条这种"压在视频上"的少数几块保留 `RenderEffect` 或半透明实底。
