# LiveHub 市场调研

> 调研对象：Android TV 端「哔哩哔哩 / 斗鱼 / 虎牙 / 抖音」四平台直播聚合客户端
> 调研时间：2026 年 10 月
> 结论用途：确定产品定位、界面信息架构与交互原则，供 UI 设计阶段使用

---

## 一、五条结论

1. **需求是真实存在的，且被官方主动放弃。** 四平台里，虎牙 TV 版与斗鱼 TV 版已基本退场，B 站 TV 端（云视听小电视）以点播番剧为主，抖音 TV 端以短视频为主。客厅里"想看游戏直播"这件事，官方已经没有人做了。
2. **这个产品只有侧载渠道。** 互联网电视受播控牌照管理，第三方聚合客户端不可能进入电视应用商店。它注定是"U 盘 / 局域网推送 / 野草助手"分发的产品，用户是自己动手装软件的人。
3. **现有开源方案赢在"能看"，输在"难看、难操作"。** 参考的示例 APK 就是 Simple Live（GitHub 16k star，GPL-3.0，Flutter 一套代码跨六端），它的 TV 版是把手机端界面搬到电视上，官方自己标注为 BETA。**没有人真正为 3 米外的沙发设计过这套交互。** 这就是本次设计的全部空间。
4. **用户最痛的不是"平台太多"，是"换台太慢"和"状态不可信"。** 装四个 App 只是麻烦；真正的挫败来自点进去一片黑、"暂无信号"、要手动切线路、退出再进找不到刚才那个主播。
5. **大屏交互只有一条窄路：方向键 + 一个确认键。** 所有设计必须在这条路上成立。谁把手机端的列表、搜索框、设置树原样搬过来，谁就会在第一步失败。

## 二、市场盘子

| 指标 | 数值 | 来源 |
| --- | --- | --- |
| 网民规模（2025.12） | 11.25 亿，普及率 80.1% | CNNIC 第 57 次《中国互联网络发展状况统计报告》 |
| 网络直播用户规模（2025.12） | 8.14 亿，网民使用率 72.3% | 同上（"十四五"系列报告口径为 8.1 亿） |
| 直播电商用户（2025 年底） | 6.6 亿，同比 +4.8% | 华经产业研究院整理 CNNIC 数据 |
| 网络直播用户同比 | **−2.33%**（首次下滑） | 同上 |

**怎么读这组数**：直播的盘子已经封顶，8 亿人基本等于"全体网民"。增量不在"更多人看直播"，而在**同一批人把时间挪到哪块屏幕上**。手机端已经饱和且极度内卷（广告、会员、信息流），大屏是唯一还能提供"无干扰长时段观看"的场景。

对设计的影响：这个产品不做增长功能。没有推荐流算法、没有签到、没有广告位。它的价值是"少一步、少一个 App、少一次找不到"。

## 三、政策与牌照：这个产品的天花板在哪

这是本项目最重要的一节，直接决定产品能做什么、不能做什么。

### 3.1 硬约束

- **互联网电视（OTT）实行集成播控牌照管理**，内容必须经由持牌方（未来电视、百视通、华数、南方新媒体、国广东方、芒果 TV、银河等）播出。这就是为什么 B 站的 TV 客户端叫「云视听小电视」，出品方写的是**南方新媒体**，不是 B 站。
- **电视直播频道（央视/卫视/地方台）是另一条更严的线**，涉及《信息网络传播视听节目许可证》。2023 年 11 月「电视家」全面停服，正是这条线收紧的结果。市面上一批"电视家重生版""火星直播""超级 ITV"，多数查不到许可证编号，随时可能消失。
- **第三方客户端不持牌**。Simple Live 这类项目在 README 中明确写着"所有功能基于公开信息实现，仅供学习交流，请勿用于商业用途"。

### 3.2 四平台 TV 端的真实状态

| 平台 | TV 端 | 状态 | 说明 |
| --- | --- | --- | --- |
| 哔哩哔哩 | 云视听小电视 | **在运营** | 南方新媒体持牌；以番剧/影视点播为主，直播是附属功能，游戏直播分区不完整 |
| 虎牙 | 虎牙 TV 版 | **已停服** | 据行业媒体报道，官方于 2026 年 8 月关闭 TV 端服务端接口，存量安装包打开显示"网络异常"。早年因商业模式跑不通（TV 端广告预算极低 + 合规改造成本高）逐步退出 |
| 斗鱼 | 斗鱼 TV 版 | **已下架** | 2020 年起逐步缩减，曾短暂上架后下架，官网仅保留网页版 |
| 抖音 | 鲜时光 TV / 抖音 TV | **存在但不对味** | 大屏端以短视频、影视为主，直播入口浅，横屏直播体验并非重点 |

> ⚠️ 核实提示：虎牙 TV 停服时间来自单一行业媒体，正式立项前应向官方渠道再确认一次。

### 3.3 对本产品的三条硬性设计要求

1. **不做电视频道。** 不接央视/卫视/地方台直播源。这条线一旦跨过，产品性质从"第三方客户端"变成"未经许可的电视直播服务"，风险等级完全不同。**产品范围严格锁定在四家平台的秀场/游戏直播内容。**
2. **品牌与来源必须诚实。** 每个直播间都要明确标出它来自哪个平台，不做去平台化的伪装。App 内需要"关于"页说明内容来源与开源许可。
3. **不预置任何直播源。** 不提供配置源导入（这是 TVBox 系的做法，也是它们反复被下架的原因）。只走各平台官方公开接口。

## 四、竞品格局

### 4.1 三类玩家，各差一块

| 类别 | 代表 | 强项 | 致命短板 |
| --- | --- | --- | --- |
| **开源聚合客户端** | Simple Live（dart_simple_live）、AllLive | 四平台全覆盖、无广告、关注列表跨端同步、弹幕自研 | TV 版是手机 UI 的移植，BETA 状态；焦点跳动、卡片过小、设置项过密 |
| **影视盒子系** | TVBox、影视仓 | 点播资源极丰、可自定义源 | 需导入配置源，普通用户门槛极高；直播是附带的，体验差；合规风险高 |
| **电视频道直播** | 电视家系、火星直播、超级 ITV | 打开即看、老人友好、字号大 | 与本题不是同一赛道（他们是电视频道，不是主播直播）；购物台混排；许可证存疑 |

### 4.2 参考样本拆解：Simple Live（示例 APK）

拆包确认：`assets/flutter_assets/`、`assets/pure_live_web/`、平台图标 `bilibili/douyu/huya/douyin/egame/kuaishou/cc`，确为 Flutter 构建的 Simple Live 系客户端。

它的产品结构值得继承：

- **四平台并列**，不做优先级，用户自己选
- **关注列表跨平台混排**，开播状态是第一信息
- **自研轻量弹幕引擎**：支持字号 / 速度 / 透明度 / 显示区域 / 关键词屏蔽
- **多端同步**：扫码配对或 WebDAV，手机上的关注同步到电视
- **工具箱**：粘贴直播间链接直接跳转、解析直播流

它的问题也正是我们的机会：

- 移动端的横向滚动 + 小卡片直接搬到 1080p 上，3 米外看不清标题
- 顶部导航 + 侧边抽屉 + 底部 Tab 三套导航并存，遥控器焦点在屏幕上来回跳
- 设置项按移动端列表排布，一屏十几个开关，遥控器操作痛苦
- 播放中的操作要退出再进，"换一个主播看看"的成本极高

### 4.3 空白位

> **没有一个产品是为"沙发上的人 + 一个方向键"设计的四平台直播客户端。**

这句话就是本项目的产品定义。

## 五、用户与痛点

### 5.1 三类核心用户

| 用户 | 场景 | 核心诉求 | 现在的做法 |
| --- | --- | --- | --- |
| **跨平台粉丝**（25–35 岁，主力） | 晚上 20:00–24:00，追 3–5 个主播，分散在 2–3 个平台 | 一次看清"谁在播"，一键进去，随时换人 | 装 3–4 个 App 轮流刷，或刷微博/B 站动态看开播提醒 |
| **赛事观众**（20–40 岁） | 有比赛时长时间挂机 | 稳定、不卡、画质能上 1080P60 | 官方 TV 端没了，只能投屏或看网页版 |
| **客厅老人 / 家庭用户**（非核心但在场） | 随意看看，不懂平台差异 | 打开就有画面，字大，不乱跳 | 只会按数字键和上下键换台 |

### 5.2 痛点清单（按挫败强度排序）

以下来自公开的用户实测记录与适老化调研报道，按"用户会不会因此卸载"排序：

1. **点进去是黑的。** "标着 2000+ 频道，实际点开好多是灰色的，点进去要么黑屏，要么跳购物台。"（电视直播类实测）
2. **换台卡住。** "切到第三个源直接卡住二十秒，进度条不动，声音还在响。"（同上）
3. **找不到刚才那个主播。** "换台快没用，直播卡到想砸遥控器，谁还记得上个月看的频道去哪了。"（同上）
4. **老人按键次数太多。** 适老化调研：开机广告 15–30 秒，"想要正常收看至少需要五到七步操作，任何一步出错就很难回到原有界面"；两套遥控器叠加，"一旦不小心切换信号源，屏幕出现蓝屏、黑屏，老人会极度恐慌"。
5. **"长辈模式"只放大字体，不改层级。** 调研明确指出：底层菜单层级和广告推送机制完全没有调整。
6. **弹幕在大屏上失控。** 手机端的弹幕密度直接搬到 55 寸屏，遮挡画面；屏蔽词要一项项加。

### 5.3 痛点 → 设计要求

| 痛点 | 设计要求 |
| --- | --- |
| 点进去是黑的 | **状态诚实**：不可用的直播间不显示，或明确标注"线路异常"。绝不用灰色占位假装存在 |
| 换台卡住 | **自动降级**：主线路 3 秒无首帧自动切备用线路并降一档画质，屏幕角落给一行小字说明发生了什么 |
| 找不到上次的主播 | **关注 + 搜索 + 断点续看**：关注页按在播/未开播分组，搜索按房间号或拼音首字母直达，播放页记「上次看到这里」 |
| 老人按键太多 | **首页即遥控器**：方向键任意方向都能立刻产生画面；播放页上下键直接换台 |
| 弹幕遮挡 | **大屏弹幕默认稀疏**：字号 40px、密度上限、只占上半屏 1/3，默认开启关键词过滤 |
| 不知道怎么退 | **返回键即上一级**，最高级回到首页而不是退出 App；退出必须二次确认 |

## 六、产品定义

### 6.1 一句话

> **LiveHub —— 四个平台，一台电视。像换台一样换主播。**

### 6.2 三条设计原则

1. **换台优先（Channel first）**
   方向键的第一作用是"立刻换一个正在播的直播间"，不是"移动光标"。上下键在推荐序列里换台，左右键在四个平台之间换台。任何时候按方向键，画面都要动。

2. **号是各家自己的（No invented numbering）**
   最初这里写的是「台号寻址」：给四个平台编 1xx/2xx/3xx/4xx 四段号，数字键三位直达。**这一条被推翻了**——直播没有台号，四家的房间号体系互不兼容（斗鱼 4–8 位、虎牙最多 8 位、哔哩短号+8–10 位真实号、抖音连房间号都没有）。虚构一套统一编号，等于要求用户学一个只有这个 App 才存在的坐标系。
   现在的第二条原则是：**界面原样显示各家自己的房间号 / 抖音号，搜索按字符串匹配**。认号的人照样能输号直达，不认号的人用拼音首字母搜主播名，两条路都通。

3. **状态诚实（Say what is true）**
   "在播 / 未开播 / 线路异常 / 已降级"四种状态必须一眼可辨，用词直白。宁可少显示一个卡片，也不显示一个点进去会黑的卡片。

### 6.3 功能边界（本期设计范围）

**做**：首页推荐、四平台分类浏览、关注列表、搜索、播放页、换台、设置、扫码登录、多端同步入口。

**不做**：电视频道/EPG、点播影视、弹幕发送的输入法（仅支持预设短语与手机端联动）、礼物与充值、录屏下载、任何广告位。

## 七、设计基准

本产品 UI 参考 Apple tvOS 的设计语言（真黑底、内容优先、焦点驱动），同时满足 Android TV 的物理约束。两边的硬数字合并如下，作为设计规范的来源：

| 项目 | 数值 | 依据 |
| --- | --- | --- |
| 画布 | 1920 × 1080（16:9），按 4K 等比放大 | Android TV 标准 |
| 安全区 | 四边内缩 60px（约 5.5%），重要内容不出安全区 | tvOS 建议 60pt；Android TV 建议 5% overscan |
| 正文最小字号 | 22px @1080p（≈29pt） | tvOS DISTANCE-01：正文 ≥29pt |
| 标题字号 | 36px 起，主标题 64–72px | 同上，标题 48pt+ |
| 最小焦点目标 | 250 × 150px（≈250×150pt） | tvOS FOCUS-05 |
| 焦点放大 | 1.05–1.10，配合明度提升与抬升 | tvOS FOCUS-01 |
| 焦点移动 | 必须空间可预测；不得跳动、不得困住 | tvOS FOCUS-02 / FOCUS-08 |
| 默认焦点 | 每屏必须有一个；返回时恢复上次焦点 | tvOS FOCUS-06 / FOCUS-07 |
| 导航位置 | 顶部标签栏，不用底部 Tab / 汉堡菜单 | tvOS 反模式清单 |
| 字体 | 无衬线，中等字重起步，禁用细体与发丝线 | tvOS DISTANCE-07 |

## 八、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 平台接口变更导致大面积失效 | 致命 | 内核与 UI 分离；接口失败时整屏降级为"关注列表 + 明确错误说明"，不显示空白骨架 |
| 播控合规 | 无法上架、可能被要求下架 | 明确不做电视频道；App 内声明内容来源与"仅供学习交流"；不预置源 |
| 抖音直播横屏适配差 | 部分内容不可用 | 抖音分区在 UI 上单独标注"横屏可用"，不可用的不列出 |
| TV 芯片性能弱（1GB 内存盒子） | 焦点动画掉帧 | 动效只做 transform / opacity；图片分级加载；焦点放大不做实时模糊与视差贴图 |
| 弹幕量过大 | 卡顿 | 密度上限 + 抽样渲染，超出直接丢弃 |
