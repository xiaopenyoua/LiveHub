# docs/ — 判断依据

这个仓库有三个内容目录，分工按"它回答什么问题"切：

| 目录 | 回答 | 换掉实现语言后还成立吗 |
| --- | --- | --- |
| `design/` | 界面**长什么样** | 成立（但定稿会随版本冻结） |
| `android/` | 我们**怎么实现**的 | 不成立（换语言就句句作废） |
| `docs/` | **为什么做这个**、参考的那个 App **是怎么做的** | 成立（说的是外部世界，不是我们的代码） |

`docs/` 是那个"事实在中间"的位置：既不描述我们的界面，也不描述我们的代码，但设计决策和工程决策都要
回头指它。判据（三问，依次问，先命中先定）：

1. 能被 `assembleDebug` 直接吃掉吗（`res/`、`java/`、构建配置）？ → `android/`
2. 是设计稿、规格、矢量、稿子素材吗？ → `design/`
3. 都不是，但**下一个做决定的人需要它**吗？ → `docs/`

三个都不命中，就按 `AGENTS.md` R6 删掉，不要另建第四个目录。

## 目录里就两份

| 文件 | 回答什么 | 谁在引它 | 过期速度 |
| --- | --- | --- | --- |
| `市场调研.md` | 市场盘子、政策与牌照、竞品格局、用户痛点、产品定义。五条结论 + 三根产品支柱 | 根 `README.md`；`android/docs/架构.md`（§3.1 不做 IPTV、§3.3 不进商店、§5.3 首帧 3 秒、§"状态诚实"） | 慢。一年一变，变的是"哪家平台退场了" |
| `逆向分析.md` | 参考 App（`com.mystyle.purelive` v1.7.4）的直播功能是怎么搭起来的：包结构、播放内核、四家取流与弹幕协议事实 | `android/docs/架构.md`（协议事实来源）；`android/docs/接口实测.md`（字段表与签名算法的出处） | 中。协议会改，改了要重测 |

两份都以**结论分三级**（观测 / 推断 / 未知）写，这不是文风，是判据：观测能指到字节或文件，推断能指到结构，
未知就写未知 —— 混在一起写，读者就无法判断"这条能不能拿去做决定"。

## 为什么不在 `design/`，也不在 `android/docs/`

**不进 `design/`：** 这两份里没有一处界面决策值 —— 没有坐标、没有色值、没有栅格、没有字号。
它们是那些值的**上游依据**。`design/` 放的是"结果"，`docs/` 放的是"为什么是这个结果"。
更要紧的是**冻结粒度不同**：市场结论一年不变，界面规格一周一变。放同一棵树里，要么市场结论被
"版本目录"冻住（改一条就得多开一个 `v1.1.0/`），要么 `design/` 的冻结被"反正能改"侵蚀。两者都是坏的。

**不进 `android/docs/`：** 那两份（`架构.md`、`接口实测.md`）描述的是**我们这个工程**怎么实现、
某天某时在某台设备上测到了什么 —— 它们是"我们的实现"的说明与实测记录，是**活文档**（跟着代码一起长，
`AGENTS.md` R7 对它们没有豁免：里面的路径必须今天就能用）。`docs/` 这两份描述的是
**别人的产品**和**市场本身**：换实现语言、换播放内核、换弹幕库，它一个字都不用改。
把它们塞进 `android/docs/`，等于说"这些事实只在这个 Kotlin 工程里成立"，而下一个人换平台时
就会以为得重新调研、重新逆向 —— 那正是"把一次判断变成永久负债"的反面教材。

**为什么逆向分析不是 `android/` 的证据：** 它确实是开发侧主动做的取证（REA / Dart AOT 反编译 /
四家接口实测），但产出物是**外部世界的协议事实**（签名怎么算、取流走哪条、弹幕通道是哪条），
不是"我们的工程怎么搭"。事实归 `docs/`，我们基于事实做的取舍归 `android/docs/架构.md`。
所以 `android/docs/架构.md` 的抬头第一句就是"协议事实来源：`docs/逆向分析.md`" —— 引用，不是复制。

## `docs/` 的规矩

1. **语义名。** 不编号（`NN-` 前缀全仓库只有 `design/<版本>/spec/` 能用），不写版本号，不写状态词。
2. **只写"为什么"和"参考的是什么"。** 实现细节 → `android/docs/`；设计规格 → `design/<版本>/spec/`；
   同一个结论不要在两地各写一份（写两处就有一处会先过期，而它过期那天不会通知任何人）。
3. **这里不是记录位 —— 断链必须真修。** 冻结记录"只加 errata 不改正文"的规矩（`AGENTS.md` R7）
   **不适用于 `docs/`**：那两份是"某次裁决的证据快照"，这两份是**现在仍然有效的判断依据**。
   依据里的路径指错了，下一个人就找不到依据本身。`verify-layout.sh` 第 7 项会把这里的断链判 FAIL
   （当前 0 条）。引用别处一律写全路径 + 节号：`android/docs/架构.md §4.1`，不写"见架构那篇"。
4. **不存二进制。** `示例参考软件.apk` 在 `.gitignore` 里、不进仓库；`逆向分析.md` 记它的字节数
   （167,927,123）与 SHA-256 前缀就够 —— 证据的要求是"可核对"，不是"把原件搬进来"。
   同理不存抓包、不存 APK 里抽出来的库文件。
5. **一份只回答一个问题。** 新增文件前先答 `AGENTS.md` 那个四问里的第三问：删掉它损失什么？
   答不出"损失的是哪条判断依据"的，就不要建。
